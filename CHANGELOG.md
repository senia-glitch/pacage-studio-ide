## [Не выпущена]

### Добавлено

- **Серверы проекта по кнопке.** Блок «Проект» в окне агента: «▶ Запустить проект» поднимает бэкенд
  (`uvicorn app.main:app --reload`), затем фронтенд (`npm run dev`); у каждого сервера своя кнопка, статус и
  ссылка, которая появляется, когда он ответил. Занятый порт заменяется свободным, адрес берётся из
  вывода сервера, серверы останавливаются вместе со студией. Команды и порты — в «Настройках агента»
  (`.studio/servers.json`). Маршруты `/api/devservers*` закрыты для агента.

### Исправлено

- Вопрос агента с вариантами ответа: клик по варианту теперь выделяет его (текст попадает в поле, его можно
  дополнить), а отправляет кнопка «Ответить». Раньше клик отправлял ответ сразу, и устаревший вопрос
  нельзя было ни выбрать, ни убрать.
- Студия не принимает вопрос агента вне его этапов и скрывает устаревший вопрос.
- «Принять» отчёт недоступно, пока агент ещё работает: раньше агент мог прислать бэкенд-отчёт, а отчёт
  по фронтенду уже получал отказ, потому что цикл был завершён.

## [7.3.0] — 2026-11-08

Второй агент и разделение ролей: план (идеи, карточки) и реализацию кода можно отдать разным агентам и
моделям — например, анализ на Claude Code, код на OpenCode с моделью из вашей подписки.

### Добавлено

- **OpenCode как второй агент.** На странице «Настройки агента» выбор агента (Claude Code или OpenCode) и, для OpenCode, модели из подписки: список строит `opencode models`, студия показывает его по провайдерам; есть необязательный режим рассуждений (`--variant`). Настройка хранится в `.studio/runner.json` (`agent`, `model`, `variant`); старые файлы читаются как Claude Code.
- Модуль `studio/agent/adapters.py`: адаптеры агентов (аргументы запуска, продолжение сессии, разбор вывода, права, список моделей). Общая часть запуска (этапы, git-чекпоинты, таймаут) осталась в `runner`.
- Для OpenCode студия пишет свой `.studio/opencode.json` (MCP студии, права из тех же списков разрешённого и запрещённого, `share: disabled`, `small_model` = выбранная модель) и передаёт его через `OPENCODE_CONFIG`; `opencode.json` проекта не трогается; файл в `.studio/.gitignore`.
- `GET /api/agent/models?agent=…` — список моделей агента.
- **Два независимых исполнителя.** Агент и модель выбираются отдельно для плана (этап «Идеи») и для реализации (этап «Реализация», доработка): анализ на одном агенте, код на другом, либо один агент на оба этапа. У Claude Code теперь тоже выбирается модель (`--model`). В `.studio/runner.json` — `roles` (`plan`, `implement`) и `commands` по агентам; старые файлы (один агент) читаются как оба этапа на этом агенте.
- **Модель и уровень усилий для каждого исполнителя.** Claude Code: `--model` и `--effort` (низкий … максимальный); OpenCode: модель и `--variant` из того, что умеет выбранная модель (`opencode models --verbose`). Каталог моделей помечает тариф: бесплатная, по подписке (OpenCode Go, вход через аккаунт) или платная по токенам; платные скрыты, пока не включён переключатель «Показывать платные модели». Fable у Claude Code скрыта как требующая кредитов. `GET /api/agent/models` отдаёт `items` (кэш 5 минут, `refresh=1` обновляет).
- Сессии хранятся по агентам (`agent-session.json`: `sessions`); один агент на обе роли продолжает общий контекст, у разных агентов сессии свои, потеря сессии одного не трогает другого.
- «Начать» (и `POST /api/workflow/start`, ответ 409 `agent_not_ready`) недоступно, пока агент любой нужной роли не готов; «Проверить связь» и окно агента показывают состояние по ролям.

### Изменено

- Без выбранной модели OpenCode не запускается (токены не тратятся); смена агента сбрасывает подключение и модель.
- Если OpenCode после ошибки провайдера («Insufficient account funds», лимит бесплатных моделей) молча ждёт, студия прерывает запуск и показывает причину.
- Запрос к агенту через `.cmd`-обёртку (npm на Windows) очищается от метасимволов `cmd.exe`.
- Хвост stderr MCP-сервера в диагностике очищен от цветовых кодов.

## [7.2.0] — 2026-11-08

MCP-сервер стал обязательной частью пакета, а «готов» теперь значит «агент реально получит
инструменты `studio_*`». Раньше после `pip install` без `[mcp]` сервер падал сразу, Claude Code
видел `CONNECTION_CLOSED`, а студия показывала «готов» и запуск этапа тратил токены впустую.

### Изменено

- **`mcp` — обязательная зависимость** (`dependencies`). Extra `pacage-studio[mcp]` оставлен
  пустым алиасом: старые команды установки работают. Из `dev` убран дубль. README, `docs/` и
  справка CLI больше не называют `[mcp]` обязательным шагом. `studio install-full` после установки
  запускает `pip check` и предупреждает о конфликтах.
- **«Готов» только после рукопожатия.** «Подключить» записывает `.studio/mcp.json`, выполняет
  `initialize` и включает агента, только если сервер ответил. Индикатор в окне агента показывает
  «проверяю связь…», пока рукопожатия не было, и «MCP не запускается: …» при сбое.
- **Python не старше 3.12.** `requires-python = ">=3.12"` (уже стоял), а запуск на старом Python
  даёт понятное сообщение без трассировки (`studio.require_python`). `ruff` проверяет под py312.

### Добавлено

- **Настоящая проверка MCP** (`studio/agent/mcpcheck.py`). «Проверить связь», `studio doctor`
  (раздел «MCP-сервер», при сбое код выхода 1, ключ `mcp` в `--json`) и старт студии запускают
  сервер той же командой и с тем же окружением, что получит агент, и шлют `initialize`. При сбое —
  причина и готовая команда исправления: нет `mcp`, Python старше 3.12, не установлена студия в
  Python из `mcp.json`, устаревший путь к Python, сервер упал (последние строки stderr), сервер молчит.
- **Запуск этапа без токенов при сломанном MCP.** Если рукопожатие не прошло, агент не запускается,
  в окне — причина и команда (раньше агент отвечал, что инструментов `studio_*` нет).
- **Секреты не попадают на диск и в git.** `.studio/.gitignore` теперь исключает `mcp.json`,
  `agent-session.json` и `agent-git.json` (существующие проекты получают строки при ближайшем
  скане; уже закоммиченные файлы нужно убрать из индекса командой `git rm --cached`).
  Вывод агента (`runner.log`, хвост лога в окне), stderr сервера и сохранённые отчёты проходят
  скрытие ключей и токенов (ключи Anthropic и переменные вида `…_API_KEY=…`, `Bearer …`, токены GitHub,
  `X-Studio-Token`). Студия не читает `~/.claude/` и ключи Claude Code. Пуш в GitHub выключен
  по умолчанию.

### Убрано

- Рабочие файлы из репозитория: `text.py` (скрипт-выгрузка проекта в текст) и `docs/TZ-7.1.md`
  (черновик задания). Личные пути в тестах заменены нейтральными; добавлены тесты чистоты
  репозитория (нет личных путей и почт, `.env*` и `metadata.json` — только в тестовой заготовке).

## [7.1.0] — 2026-11-08

По итогам первого реального прогона цепочки: перенос карточек стал честным (сверка с кодом, имена
из `slug`), план сам становится фактом, агент работает в окружении проекта. Ничего не удалено.

### Добавлено

- **Сверка карточек с кодом перед переносом** (`studio/server/reconcile.py`, `POST
  /api/workflow/transfer-card`). Сценарий сверяется по маршруту (метод + путь без префикса API и
  имён параметров), имени эндпоинта и классу сценария; страница — по имени и маршруту, `extends` — по
  блокам. «Уже есть в коде» не переносится: карточка получает пометку `inCode` (бейдж «уже в коде»,
  группа «Реализованные»), остальные карточки переносятся как обычно. «Частично» переносит только
  недостающие блоки. Принудительный перенос — `force` (подтверждение в интерфейсе). Пакетный
  «Дальше» считает такие карточки в `transfer.in_code` и ошибкой не считает.
- **План → факт автоматически** (`studio/metadata/facts.py`). Когда код плана найден (`done`),
  скан сам переносит описание, критерии и домен на реальные узлы (свои поля узла не затираются),
  убирает заглушки слоёв и запись плана и пишет строку в журнал `finished_plans` в `metadata.json`.
  Отчёт агента по `plan` + `layer` закрытого плана принимается по журналу.
- **Агент и тесты работают в окружении проекта** (`studio/agent/projectenv.py`): `.venv`/`venv`
  ставится в `PATH`, выставляется `VIRTUAL_ENV`, убирается `PYTHONHOME`. Выбранное окружение видно
  в «Настройках агента» и в первой строке `runner.log`; без окружения агент запускается как раньше
  с пометкой.

### Исправлено

- **Имя узла из `slug`, а не из заголовка.** Свайп вверх и «На карту ↗» создавали `studio:*`-узлы с
  русским заголовком в `name`/`function_name` и пустым `target_file`, поэтому `verify` не находил их
  в коде. Теперь перенос идёт через серверный план (латинские имена и файлы из `slug`), а
  `POST /api/metadata/graph-node` принимает `slug` и выводит из него имя и файл слоя.
- **Чекпоинты git только в корне репозитория.** Проект внутри чужого репозитория больше не
  переключает ветку и не откатывает файлы всего репозитория (тесты на временных папках внутри
  проекта могли переключить настоящий репозиторий на `studio/c1`).

## [7.0.0] — 2026-11-07

Агент работает в фоне и сам продолжает дорожную карту после ваших шагов; интерфейс разложен
на пять страниц и два режима. Никакие страницы и функции не удалены: перегруппированы кнопки и
режимы, добавлены автоматизация и окно агента.

### Добавлено

- **Окно агента** — сквозное (на любой странице, справа внизу): индикатор связи с Claude Code,
  цепочка из 7 шагов с пометкой «чей ход» (Цель → Идеи → Разбор → Выбор задач → Реализация →
  Проверка → Приёмка), главная кнопка шага, поле цели, статус, лог, «Стоп», «Откат», «Заново».
- **Фоновый запуск без расхода токенов в простое.** Студия сама запускает `claude -p` на ваш
  шаг («Начать», «Отдать агенту», «Вернуть на доработку», ответ на вопрос) и держит ту же сессию
  через `--resume` (id сессии из JSON-вывода; потерянная сессия начинается заново). Свайпы агента
  не будят. MCP-конфиг студия передаёт сама (`.studio/mcp.json`), `.mcp.json` проекта не трогается.
- **`studio_ask`** — агент в фоне задаёт вопрос человеку и завершается; вопрос виден в окне агента,
  ответ запускает агента снова с тем же контекстом (состояние «ждёт вас»).
- **Git-чекпоинты делает студия.** Перед реализацией запоминается точка отката и создаётся ветка
  `studio/c<цикл>`, после — коммит (без `.studio`), кнопка «Откат». Пуш на GitHub — опция в
  настройках. Агенту запрещены `git push/remote/checkout/reset`, установка пакетов и `rm -rf`.
  Если в проекте есть ваши несохранённые изменения, чекпоинт не создаётся (об этом сказано в окне).
- **«Вернуть на доработку»** (`POST /api/workflow/rework`): агент берёт то же ТЗ с вашим пожеланием.
- **Страница «Настройки агента»**: подключение Claude Code («Подключить», «Проверить связь» без
  токенов), сценарии работы человеческим языком, права, git и GitHub, запуск, ручная инструкция.
- **Режимы «Агент» и «Ручной»** в верхней панели (`.studio/settings.json`). В ручном режиме нет окна
  агента и виден прежний путь «промпт → ответ LLM».
- **Страница «Генератор идей»:** свайп карточек прямо на странице (вверх — на карту, вниз — удалить,
  с отменой), поиск по идеям, группы в левой панели «Backend», «Frontend» и «Реализованные» (в
  конце, сворачиваются), пометка «агент» и «реализовано» на карточках.
- Поиск узлов переехал в левые панели «Карты backend» и «Карты frontend» (во frontend — новый).

### Изменено

- Вкладки: «Карта backend», «Карта frontend», «Генератор идей», «Настройки промптов», «Настройки агента».
- Верхняя панель: убраны кнопки зума «+/−» (есть колесо мыши) и выбор редактора (только VS Code);
  масштаб, «Метаданные» и «Обновить код» собраны в меню «Вид».
- `studio_workflow` и свайпы: решение по карточке поднимает ревизию дорожной карты.

### Исправлено

- `Workflow.report_received` не уведомлял подписчиков: после отчёта агента не запускался прогон
  тестов проекта.

## [6.3.0] — 2026-11-07

Релиз закрывает оставшиеся пробелы: тесты фронтенда, окружение проекта, вызовы в коде и
контракт эндпоинта для агента.

### Добавлено

- **Тесты фронтенда в независимом прогоне.** Если в `frontend/package.json` есть скрипт `test`,
  студия после pytest запускает `npm test` с отчётом Vitest в JUnit; итог складывается, а в
  `parts` видно бэкенд и фронтенд отдельно. Не запустившаяся часть — ошибка, а не тишина.
  `.studio/tests.json`: `frontend_command` (не задано — авто, `[]` — не запускать).
- **Вызовы эндпоинтов, найденные в коде** (`inferred_calls`, в `studio_node` — `calls_in_code`):
  цепочка блок → composable → действие → api; для composable учитываются только используемые
  поля. В ТЗ фронтенда — «в коде уже есть вызовы», в `check_links` — `in_code`, в verify —
  заметка, если объявленного вызова в коде нет.
- **Контракт эндпоинта в ТЗ фронтенда:** параметры запроса и поля тела, `response_model`, код
  ответа и ключи словаря из `return` сценария (по тексту кода).

### Изменено

- pytest по умолчанию запускается Python из `.venv`/`venv` проекта, а не студии: раньше сборка
  тестов падала из-за отсутствия зависимостей проекта. Дочерний процесс получает UTF-8.

## [6.2.0] — 2026-11-07

Релиз по итогам прогона на реальном проекте и работы двух агентов по руководству.

### Добавлено

- **Прогон тестов проекта студией.** Кнопка «Запустить тесты проекта» на этапе «Отчёт», галочка
  «Запускать тесты, когда агент прислал отчёт» в «⚙ Автозапуск» (выключена по умолчанию) и команда
  `studio test`. Студия запускает `pytest` (команда и предел времени — `.studio/tests.json`),
  читает отчёт JUnit и показывает, сколько прошло, что упало и у каких планов. Агент читает итог
  инструментом `studio_tests`, но запустить прогон не может.
- **`studio migrate [--apply]`** — убирает записи-заглушки старой модели из `metadata.json` (слои
  реализованных планов, дубли `studio:…` кода); по умолчанию только показывает, с копией файла.
- **Диагностика `W_ROUTE_SHADOW`:** статичный маршрут позади параметрического недостижим. Порядок
  регистрации учитывает алфавит файлов роутов **и место `include_router`**. При отправке идеи
  студия предупреждает об этом заранее (`warnings`), а в ТЗ плана появляется рецепт.
- `studio_doctor` различает **новые и давние** предупреждения (`.studio/diag-baseline.json`,
  запоминается при «Отдать агенту»): `ok_for_changes`, `new`.
- `studio_ideas(idea_id=…)` — идея целиком (сценарии, критерии, решение человека); у списка —
  `slugs`; `studio_workflow` отдаёт `my_cards`; ответ `studio_idea_add` — `cards` (id, slug,
  маршрут). `studio_graph` показывает эндпоинты первыми. Путь сценария записывают без префикса
  API: лишний префикс студия убирает и сообщает.

- **Блоки на существующей странице:** в идее `pages` можно указать `extends="home"` и
  `blocks` вместо новой страницы; перенос кладёт плановые блоки на неё, выбор задач и ТЗ
  фронтенда это понимают. Новая страница без `route` — предупреждение, занятое имя или
  маршрут — отказ с подсказкой про `extends`.
- `studio_idea_withdraw` — агент отзывает свою идею (пока по ней нет принятых карточек);
  предупреждение о похожей идее; `studio_node` открывает страницы и блоки фронтенда;
  `studio_doctor` даёт краткий `verdict`; описание блоков в `studio_ideas(idea_id)` полное.

### Исправлено

- Реализованные планы больше не дают ложных предупреждений (`W_PLAN_CONFLICT`,
  `W_METADATA_ORPHAN`, `W_EDGE_UNRESOLVED`): на реальном проекте с 12 планами — 26 предупреждений
  вместо 2 (остались настоящие). Тест плана сопоставляется с кодом, даже если в файле их несколько и
  они названы по поведению.
- Новый цикл цепочки начинается с чистого счёта карточек и без ТЗ прошлого цикла; окно переноса
  показывает только ещё не перенесённые карточки.

## [5.11.1] — 2026-11-05

### Исправлено

- **Bind-параметры SQL больше не принимаются за таблицы.** Имя параметра,
  совпавшее с SQL-ключевым словом (`:from`, `:join`, `%(to)s…`), заставляло
  парсер считать следующим словом таблицу — обычно `AND` — и выдавало
  ложные `W_TABLE_UNKNOWN` («Таблица 'AND' не найдена среди моделей»).
  Перед поиском таблиц именованные bind-параметры (`:name`, `%(name)s`)
  вырезаются из текста запроса.
- **Диагностика дублей якорей без шума.** `W_DUP_ANCHOR` больше не срабатывает:
  - на одном физическом элементе кода — nested-узел создаётся по одному на
    каждого родителя, и у функции/модуля, используемых из разных сценариев,
    якорь и позиция `file:line` совпадают («дубль» узла с самим собой);
  - на одноимённых обработчиках эндпоинтов из разных роутеров — параллельная
    структура student/tutor/admin ведёт на разные URL и разные сценарии.
    Совпадение по якорю при разных маршрутах (`url_path`, `http_method`)
    предупреждением не считается; настоящий конфликт одного маршрута
    по-прежнему репортится.
- **Отпечаток кода не зависит от перевода строк в чекауте.** SHA-1 исходника
  считался по сырым байтам, поэтому один и тот же коммит давал разные
  значения отпечатка в LF-чекауте (Linux/CI) и CRLF-чекауте
  (Windows, autocrlf) — из-за этого падали сравнения ТЗ с эталоном.
  Теперь хэшируется нормализованный текст (LF); значения для
  LF-коммитнутых файлов не изменились.
- **Планка покрытия CI приведена к фактическому уровню (85%).** Требование
  90% оставляло CI красным с релиза 5.8: дробь unit-набора ~87.8% (Windows)
  и ~88.6% по всему набору.

### Изменено

- io-якорь стал стабильным: `Scenario._db.method#n` вместо `...:строка`.
  Номер строки остался в `node.line`; старый формат `:LINE` читается.
  — устарело в 5.0: старые якоря `:LINE` не разрешаются.
- Домены наследуются направленно (endpoint → scenario → io → model,
  uses/depends), через другой эндпоинт обход не идёт.
- «Неполный» узел считается только Python-сканером (`Node.complete`),
  UI и экспорт используют это поле.
- `ScenarioPath.endpoints` — все эндпоинты-корни, `endpoint` — первый.
- Запись метаданных сохраняет BOM, стиль переводов строк и финальный `\n`,
  пишет атомарно и проверяет `base_hash` файла.
  — устарело в 5.0: метаданные живут в `.studio/metadata.json`.
- Версия пакета — один источник: `studio.__version__`.
- `studio export` стал устаревшим псевдонимом `studio brief --map full`;
  документ теперь называется ТЗ для AI-агента.
  — устарело в 5.0: команда удалена.

### Несовместимые изменения

- Схема графа v6: старый `.studio/graph.json` пересоздаётся автоматически.
- Формат id io-узла — `#n`. Старые edge-блоки с `:LINE` читаются и
  разрешаются на ближайший вызов того же метода.
  — устарело в 5.0: блоки `# studio:` не читаются.
- Все `/api/*` требуют заголовок `X-Studio-Token`; POST — `application/json`.
- Новые коды возврата CLI: 0 — порядок, 1 — ошибки диагностики (или warning
  при `--strict`), 2 — неверные аргументы/проект не найден.
- `save_node_metadata` возвращает `SaveResult` (а не `bool`).
