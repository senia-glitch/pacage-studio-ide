## [5.1.0] — в работе

### Исправлено

- `.studio/metadata.json` больше не попадает в `.studio/.gitignore`: это
  единственное хранилище описаний и планов, он коммитится вместе с проектом.
  Игнорируются только `graph.json`, `studio.log`, `agent-brief.md`, `briefs/`
  и `last-brief.json`; существующий `.gitignore` пользователя не перезаписывается.
- Битый `metadata.json` (`W_METADATA_INVALID`) больше не затирается пустой
  структурой при сохранении из UI или создании плана: запись отклоняется,
  файл остаётся как был.
- Запись `metadata.json` сверяет хэш прочитанного файла: правка из другой
  вкладки, второго `studio` или IDE не теряется — файл перечитывается один раз.
- Внешняя правка `metadata.json` сразу поднимает ревизию live-обновления.
- Тело HTTP-запроса ограничено 1 МБ; неверный или отрицательный
  `Content-Length` даёт 400 вместо 411/500.
- `studio brief --out` и `/api/brief/save` не пишут ТЗ за пределы проекта
  (`..`, абсолютный путь, симлинк).
- `studio verify` больше не считает короткий якорь вроде `get` тестом
  `test_get_user`.
- Образцы кода в ТЗ скрывают `KEY=...`, `token`, `password`, `secret`,
  строки в кавычках и значения в f-строках; усечение ТЗ не рвёт блок кода.
- Ссылка «Открыть в VS Code» кодирует `#`, `%`, пробелы, кириллицу и
  обратные слэши.
- UI: устаревший ответ сборки ТЗ не перетирает свежий, повторное сохранение
  не дублируется, недоступный сервер показывает баннер, а несохранённый текст
  не теряется при смене вкладки.
- Скан пропускает нечитаемый каталог с диагностикой `W_DIR_UNREADABLE`;
  ошибки отката плана пишутся в лог.

## [5.0.0] — 2026-10-24

### Добавлено

- `.studio/metadata.json` — единственное хранилище описаний, критериев, доменов,
  дополнительных связей и планируемых узлов. Запись атомарная, только по явному
  действию пользователя.
- `nested`-узлы: self-методы сценария, функции файла и импортированные модули
  проекта. Один уровень, связи `uses`, переключатель «скрыть вложенные».
- Жёлтые пометки с причиной: сценарий без `execute`, дубли якорей,
  неоднозначные связи, динамические маршруты/SQL/таблицы, неизвестные таблицы,
  неразрешённые импорты, битые файлы, ошибки metadata.json.
- «Создание» создаёт файлы-скелеты с одной строкой `# TODO:` и записывает план
  в metadata.json. Всё или ничего; существующие файлы не перезаписываются.
- ТЗ для AI-агента собирается из планируемых узлов с описанием; в задачи
  попадают nested-узлы как «можно переиспользовать».
- `studio verify` отвечает только на три вопроса: узел, связи, тест.

### Изменено

- Метаданные больше не живут в коде проекта.
- `studio export` удалён; вместо него `studio brief --map full`.
- UI: чип «К реализации / Выполнено», группировка диагностики, фильтр,
  пустые состояния, «Почему жёлтый», «скрыть вложенные».
- «Открыть в VS Code» — единственный поддерживаемый редактор.

### Несовместимые изменения

- Служебные комментарии `# studio:` в коде больше не читаются. Метаданные из
  них не мигрируют автоматически — перенесите их в студию вручную.
- Удалены диагностики `W_UNCLOSED_BLOCK`, `W_NESTED_BLOCK`, `W_ORPHAN_BLOCK`.
- Удалена отмена сохранения (`/api/undo`) и запись в код проекта.
- Старые якоря вида `Scenario._db.method:LINE` больше не разрешаются.

### Обновление

Перезапустите `studio`, обновите страницу (**Ctrl+F5**). Если у вас были
описания в комментариях кода, перенесите их в студию вручную.

## [4.0.0] — 2026-10-23

### Добавлено

- Live-обновление карты после правок в IDE (long-poll, индикатор связи).
- «Открыть в редакторе» одним кликом: VS Code, Cursor, Zed, Windsurf,
  PyCharm и свой шаблон; выбор редактора запоминается.
  — устарело в 5.0: остался только VS Code.
- Поиск по карте, палитра `Ctrl+K`, фильтр доменов, панель диагностики.
- Раскладка, зум, вкладка, выбранный узел и черновик «Создания» переживают F5
  (localStorage; в проект ничего не пишется).
- Диагностики в графе: коды `E_*`/`W_*`/`I_*` с файлом, строкой и подсказкой.
- `studio doctor [--json] [--strict]`, `scan/list --json`, `export --out`,
  `--version`, автооткрытие браузера, поиск корня проекта вверх.
  — устарело в 5.0: `export --out` удалён, используйте `studio brief --out`.
- Поддержка конструкций стека: `include_router(prefix=...)`, любые
  `APIRouter`, stacked-декораторы, `api_route`, алиасы `run`, self-методы
  сценария, JOIN/UPDATE/INTO/DELETE, `Base` + `table=True`, тесты в классах
  и матч по URL.
- Отмена сохранения (`/api/undo`) и возврат удалённых сирот из UI.
  — устарело в 5.0: удалено.
- Статика UI вынесена в `studio/ui/static` (CSS + ES-модули), CSP, токен,
  проверка Host/Origin/Content-Type.
- JS-тесты на `node:test` для чистых модулей.
- «Мост разработчик → AI-агент»: `studio brief` собирает ТЗ по планируемым
  узлам (описание, критерии, целевой файл, связи, образец кода, проверка),
  `studio verify` проверяет выполнение, в UI появилось окно «ТЗ для
  AI-агента» с предпросмотром и прогрессом «Выполнено N/M».
- В узлах графа появились `end_line`, `details.signature/fields/doc`;
  у рёбер — `origin` (`code`/`metadata`).
- TODO-узлы всегда видны в UI: бейдж «TODO · нет кода/описания», файл-план,
  область «Вне путей запроса», чип «в цепочке TODO» и режим подсветки.
  Счётчик `todo_downstream` считается сканером.

### Изменено

- io-якорь стал стабильным: `Scenario._db.method#n` вместо `...:строка`.
  Номер строки остался в `node.line`; старый формат `:LINE` читается.
  — устарело в 5.0: старые якоря `:LINE` не разрешаются.
- Домены наследуются направленно (endpoint → scenario → io → model,
  uses/depends), через другой эндпоинт обход не идёт.
- «Неполный» узел считается только Python-сканером (`Node.complete`),
  UI и экспорт используют это поле.
- `ScenarioPath.endpoints` — все эндпоинты-корни, `endpoint` — первый.
- Запись метаданных сохраняет BOM, стиль переводов строк и финальный `\n`,
  пишет атомарно и проверяет `base_hash` файла.
  — устарело в 5.0: метаданные живут в `.studio/metadata.json`.
- Версия пакета — один источник: `studio.__version__`.
- `studio export` стал устаревшим псевдонимом `studio brief --map full`;
  документ теперь называется ТЗ для AI-агента.
  — устарело в 5.0: команда удалена.

### Несовместимые изменения

- Схема графа v6: старый `.studio/graph.json` пересоздаётся автоматически.
- Формат id io-узла — `#n`. Старые edge-блоки с `:LINE` читаются и
  разрешаются на ближайший вызов того же метода.
  — устарело в 5.0: блоки `# studio:` не читаются.
- Все `/api/*` требуют заголовок `X-Studio-Token`; POST — `application/json`.
- Новые коды возврата CLI: 0 — порядок, 1 — ошибки диагностики (или warning
  при `--strict`), 2 — неверные аргументы/проект не найден.
- `save_node_metadata` возвращает `SaveResult` (а не `bool`).

### Обновление

Перезапустите `studio` и обновите страницу (**Ctrl+F5**).
