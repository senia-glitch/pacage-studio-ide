# Установка pacage-studio

`pacage-studio` — офлайн-инструмент, который по AST строит карту пути
HTTP-запроса для стека `fastbase / core-package / event-infra`:

```
endpoint → scenario → io → model
```

Сканер только читает код. Метаданные узлов и связи хранятся в коде
комментариями с меткой `studio`. Код проекта не генерируется.

## Установка в venv проекта

```powershell
python -m pip install --upgrade --force-reinstall "pacage-studio @ git+https://github.com/senia-glitch/pacage-studio-ide.git"
```

Если python называется `py`:

```powershell
py -3 -m pip install --upgrade --force-reinstall "pacage-studio @ git+https://github.com/senia-glitch/pacage-studio-ide.git"
```

## Локальная установка из клона

```bash
git clone https://github.com/senia-glitch/pacage-studio-ide.git
cd pacage-studio-ide
pip install -e .
```

Для разработки самой студии:

```bash
pip install -e ".[dev]"
pytest tests/
```

## Проверка

```powershell
studio help
```

## Быстрый старт

```powershell
cd <папка_вашего_проекта>
studio                 # автоскан + интерфейс на http://127.0.0.1:8777
studio scan            # только пересобрать .studio/graph.json
studio list            # сценарии в терминале
```

При запуске пакет **сначала сканирует проект** и только затем открывает
интерфейс. Проект запускать не нужно: студия работает с кодом как с текстом.

## Интерфейс

Три фиксированные вкладки одного окна:

- **Карта** — только эндпоинты fastbase. Группировка: домен → HTTP-метод.
  На узле видны метод, URL и имя функции. Клик открывает сценарий.
- **Сценарий** — путь от эндпоинта до модели: `endpoint → scenario → io →
  model`, тесты справа. Список сценариев разделён на зоны
  «HTTP-метод → домен». Узлы можно перетаскивать. Клик по узлу открывает
  метаданные (описание, критерии, домен); правки сохраняются при потере фокуса.
- **Создание** — графический конструктор: узлы-карточки с формой внутри,
  связи создаются перетаскиванием от точки справа и удаляются в панели
  «Связи». Создаются только файлы с метаданными, по одному на узел; код
  не пишется.

## Настройка окружения

Опциональный `.env.fastbase` в корне проекта:

```
FAT_ROUTES_PACKAGE=app.api.v1.routes
FAT_CORE_DISCOVER=app.scenarios
FAT_API_PREFIX=/api/v1
```

Модели читаются из `models.py` в корне проекта. Тесты — из папки `tests/`.

## Что создаётся в проекте

| Путь | Что это |
|---|---|
| `.studio/graph.json` | граф (схема v5) |
| `.studio/studio.log` | лог последнего запуска |
| `.studio/.gitignore` | служебная папка не коммитится |

Метаданные хранятся в коде проекта блоками:

```python
# studio: description start
# Текст описания.
# studio: description end
# studio: acceptance start
# - критерий 1
# studio: acceptance end
# studio: domain start
# orders
# studio: domain end
```

Связи — отдельными блоками `# studio: edge start … end`.

## Обновление

Та же команда, что и установка:

```powershell
python -m pip install --upgrade --force-reinstall "pacage-studio @ git+https://github.com/senia-glitch/pacage-studio-ide.git"
```

После обновления перезапустите `studio dev` и обновите страницу в браузере:
**Ctrl+F5**.

## Troubleshooting

| Симптом | Решение |
|---|---|
| `studio` не найдена | Активируйте нужный venv или вызывайте `python -m studio` |
| Не видно новые фичи в UI | Перезапустите `studio dev`, затем **Ctrl+F5** |
| Пустые описания узлов | Добавьте маркеры `# studio: description start/end` над якорем и выполните `studio scan` |
| `FAT_ROUTES_PACKAGE` игнорируется | Нужен dotted-путь из идентификаторов (`app.api.v1.routes`), без `..` и абсолютных путей |
| Кракозябры в консоли | Это отображение PowerShell; выполните `chcp 65001` |
