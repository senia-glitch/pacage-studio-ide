# Диагностика: код → причина → что делать

Все диагностики видны в панели диагностики (бейдж «⚠ N» считает ошибки и
предупреждения) и в `studio doctor`. `file:line` в списке открывается в VS Code.
Ошибки (`E_`) делают `doctor` кодом 1; предупреждения (`W_`) — только при
`--strict`. Жёлтая пометка на узле — это предупреждение с причиной; студия не
отбрасывает такие данные молча.

| Код | Уровень | Причина | Что делать |
|---|---|---|---|
| `E_ENCODING` | ошибка | файл не в UTF-8 | пересохраните файл в UTF-8 |
| `E_SYNTAX` | ошибка | файл не разбирается как Python | исправьте синтаксис по указанной строке |
| `E_INTERNAL` | ошибка | сбой фазы скана (страховка) | приложите `.studio/studio.log`; карта построена частично |
| `W_FILE_TOO_BIG` | предупреждение | файл больше 2 МБ и пропущен | уменьшите файл или исключите его из источников |
| `W_DIR_UNREADABLE` | предупреждение | каталог не читается и пропущен | проверьте права доступа; остальной проект просканирован |
| `W_ENV_INVALID` | предупреждение | кривой `FAT_*` или `STUDIO_MODELS` | укажите dotted-путь/файл или уберите переменную |
| `W_NO_ROUTES` | предупреждение | пакет роутов не найден | создайте пакет или задайте `FAT_ROUTES_PACKAGE` |
| `W_NO_SCENARIOS` | предупреждение | пакет сценариев не найден | создайте пакет или задайте `FAT_CORE_DISCOVER` |
| `W_NO_MODELS` | предупреждение | нет файла моделей | создайте `models.py` или задайте `STUDIO_MODELS` |
| `W_EDGE_UNRESOLVED` | предупреждение | якорь связи не найден | проверьте id/якорь в `.studio/metadata.json` |
| `W_EDGE_AMBIGUOUS` | предупреждение | голый якорь у нескольких узлов | используйте `путь/к/файлу.py::якорь` |
| `W_EDGE_SELF` | предупреждение | связь узла с самим собой | исправьте `from`/`to` |
| `W_DUP_ANCHOR` | предупреждение | одинаковый якорь/таблица/имя сценария | переименуйте или используйте `path::anchor` |
| `W_DISPATCH_DYNAMIC` | предупреждение | `run()` с нелитеральным именем | передайте литерал или модульную строковую константу |
| `W_ROUTE_DYNAMIC` | предупреждение | путь маршрута не литерал | вынесите путь в строковый литерал |
| `W_IO_DYNAMIC` | предупреждение | SQL или таблица не литерал | передайте строку явно |
| `W_IO_SAME_LINE` | предупреждение | два вызова порта в одной строке | разнесите вызовы по строкам |
| `W_TABLE_UNKNOWN` | предупреждение | таблица из io не найдена среди моделей | добавьте модель или `STUDIO_MODELS` |
| `W_NO_EXECUTE` | предупреждение | у сценария нет `execute` | добавьте `execute`; io-вызовы не собраны |
| `W_IMPORT_UNRESOLVED` | предупреждение | импорт проекта не разрешается в файл | проверьте путь модуля; nested-узел показан неполным |
| `W_ROUTE_SHADOW` | предупреждение | статичный путь (`/leads/export`) зарегистрирован позже параметрического (`/leads/{id}`) того же метода и недостижим: FastAPI сопоставляет по порядку, модули подключаются по алфавиту, а `include_router` стоит там, где написан вызов | переименуйте файл так, чтобы статичный путь шёл раньше, перенесите его выше в том же файле или подключите его роутер через `include_router` выше параметрического маршрута |
| `W_METADATA_INVALID` | предупреждение | `.studio/metadata.json` не читается | исправьте JSON вручную: запись из UI и создание плана остановлены, файл не перезаписывается |
| `W_METADATA_ORPHAN` | предупреждение | метаданные есть, узла в коде нет; запись плана не совпала с переименованным узлом | верните узел в код, удалите запись или обновите план/имя |
| `W_METADATA_EDGE` | предупреждение | связь из metadata.json не добавлена | для существующих узлов допустимы только `uses`/`depends` |
| `W_PLAN_INVALID` | предупреждение | запись плана не читается | исправьте типы полей плана в `.studio/metadata.json` |
| `W_PLAN_CONFLICT` | предупреждение | slug, имя слоя или файл плана заняты | задайте другой slug/имя или освободите файл |
| `W_PLAN_NO_DESCRIPTION` | предупреждение | у плана нет описания | добавьте `description` — без него не собрать ТЗ |
| `I_EMPTY_PROJECT` | информация | ничего не найдено | проверьте пути источников, запустите `studio doctor` |

## Частые симптомы

| Симптом | Решение |
|---|---|
| `studio` не найдена | активируйте venv или вызывайте `python -m studio` |
| порт занят | `studio dev --port 8800` |
| пустая карта | бейдж диагностики → `W_NO_ROUTES` / `W_NO_SCENARIOS` |
| нет io-узлов | вызовы должны быть `self._db.<method>(...)` в `execute` или self-методе |
| нет модели у io | `W_TABLE_UNKNOWN`: добавьте SQLModel-класс с `__tablename__` |
| узел жёлтый | откройте инспектор → «Почему жёлтый» |
| правка не видна | live обновляет сам; принудительно — «Обновить из кода» |
| кракозябры в консоли | `chcp 65001` в PowerShell |

## Работа с AI-агентом

Агент работает через MCP-сервер `studio mcp`; ошибки студии приходят агенту как
сообщение инструмента с кодом (`[код] текст`).

| Ответ | Причина | Что делать |
|---|---|---|
| `studio_not_running` | нет файла `.studio/server.json`: студия не запущена или MCP-сервер стартовал не из папки проекта | запустить `studio`; задать `STUDIO_PROJECT` (или `studio mcp --project <папка>`) |
| `bad_token` | студию перезапустили (токен новый при каждом запуске) | агент вызывает `studio_connect()` снова; только для ручной строки — взять новую в «AI-агент» |
| `stage_forbidden` | запись не подходит текущему этапу дорожной карты (идеи — на «Идеях»/«Валидации», отчёт — на «Реализации»/«Отчёте») | дождаться этапа: агент вызывает `studio_workflow` |
| `wrong_stage` | действие человека не подходит этапу (например «Отдать агенту» вне выбора) | обновить страницу; «⟲ Заново» сбрасывает цепочку |
| `mode_forbidden` | режим не разрешает действие или агент пытается тронуть созданное человеком (идею, узел, страницу), применить ответ (`apply`) | действие запрещено намеренно: агент предлагает своё рядом, применяет человек |
| `ideas_conflict` | доску идей изменили после того, как агент её прочитал | `studio_idea_add` сам повторяет со свежей доской; иначе перечитать `studio_ideas` |
| `brief_not_found` | ТЗ ещё не сохранено (бэкенд) или не собрано (фронтенд) | человек сохраняет ТЗ в окне «ТЗ» или собирает «⇄ ТЗ…» |
| `invalid_input` у `studio_report` | нет `summary` или `updates` не по формату | добавить человеческий `summary`, исправить и отправить заново; `rejected` перечисляет отклонённые записи |
| «Агент не отработал…» на полосе | автозапуск: команда не найдена, процесс упал или ушёл в таймаут | смотреть `.studio/runner.log`; поправить команду в «⚙ Автозапуск»; «↻ Запустить агента» |
| «Агент завершился, но этап не продвинулся» | автозапуск: агент отработал, но не вызвал `studio_ideas_ready` / `studio_report` | прочитать `.studio/runner.log`; «↻ Запустить агента» |
| `invalid_input` у `studio_idea_add` | плохой slug (нужен snake_case латиницей), нет `description`, `http_method`/`path`, занятое имя или файл, **маршрут или страница уже существуют** | исправить сценарий и отправить идею заново: сообщение называет причину |
| кнопка ✉ не появилась | отчёт не дошёл или уже разобран; отчёт без обновлений описаний кнопки не требует | проверить `studio_reports` и ответ `studio_report`; текст отчёта — на этапе «Отчёт» |
| полоса показывает «Как подключить агента» | агент не обращался к студии больше минуты | запустить агента в папке проекта; проверить MCP (`claude mcp list`) |
| на вкладке «Фронтенд» нет изменений агента | студия обновляет вкладку сама, но не во время ввода текста в свойствах | закончить ввод или нажать «⟳ Пересканировать» |

Что делал агент, видно в `.studio/studio.log`: строки вида `агент[plan] POST /api/ideas` (запрос студии, который сделал MCP-сервер),
`ЗАПРЕЩЕНО …` и `отказ: …` (лог перезаписывается при запуске студии).
