# Студия v3: конвейер «идея → работающее ПО»

Эталонная схема — `v3.html` (одна картинка). Открывайте файлы в браузере. Остальные `.html` —
подробности по пунктам решения. Всё, чего нет на схеме, студия не поддерживает.

## Схема в двух словах

* **Входы:** «Новая система», «Развитие» (сканер кода → банк «из кода» → восстановление замысла),
  «Запрос» (мелкая правка — быстрый путь; остальное — полный путь с нужного этапа).
* **Пять этапов**, у каждого: вход (только принятое из банка) → шаги → типовые ворота → банк.
  1. Идея: область, вопросы, границы; параллельно ограничения, конкуренты, предметная область;
     проблемы → «Проверка проблем» → функциональные требования с критериями → «Приёмка требований».
  2. Сценарии и схема БД: роли и словарь, варианты (по флагу), сценарии → «Приёмка сценариев» →
     схема БД на сценарий, слияние → «Приёмка схемы БД».
  3. Frontend на моках: стиль и каркас, план интерфейса, моки и контракт, ТЗ из банка, тесты из
     критериев (до реализации, другой агент), реализация → «Приёмка интерфейса».
  4. Backend: план бэкенда, модели из схемы БД, ТЗ из банка, тесты, реализация, замена моков →
     «Приёмка бэкенда».
  5. Общий анализ и правки: запуск с демо-данными → «Итоговая приёмка» → «Итог итерации».
* **Волны** (по желанию): этапы 3–4 повторяются для каждого пакета сценариев.
* **Банк знаний** один на проект (`.studio/bank`), раздел на каждый этап. Шаги пишут «черновик»,
  «принято» — только через ворота. Статусы: черновик → принято → устарело → принято (версия N+1);
  метки: отклонено, из кода, принято ниже порога.

## Правила, на которых всё держится

1. **Цепочка «происходит из»:** у каждой записи при создании указан родитель (проблема — из
   источника, требование — из проблемы, сценарий — из требования … тест — из критерия). Код проверяет
   покрытие на воротах. То, что «висит» или противоречит системе, принять нельзя: отклонить или
   внедрить (привязать к родителю, согласовать с принятым).
2. **Ворота из трёх слоёв:** проверки кодом (жёсткие) → независимая оценка (другая модель; каждый
   критерий 0–10, каждый ≥ 8, с доказательствами; критерии у каждых ворот свои, правятся в
   Настройках студии) → решение по режиму участия. Не больше 3 кругов подряд.
3. **Режимы участия:** «Вручную», «На воротах» (по умолчанию), «Автопилот». Автоматизация остаётся:
   висящее и запросы на изменение решают те же этапы и агенты по режиму. За человеком в автопилоте —
   итоговая приёмка и случай «агент застрял».
4. **Запрос на изменение:** принятое напрямую не меняется. Запрос → владелец (этап, где принято) →
   расчёт затронутого по связям → решение → новая версия, затронутое «устарело» и перепроверяется.
5. **Критерии приёмки и тесты до реализации:** тесты пишет не исполнитель, красный старт,
   исполнитель тесты не правит.
6. **Роли агентов** (отдельный список, модель каждой — в Настройках): Координатор, Независимый
   оценщик, Аналитик, Исследователь, Аналитик сценариев, Проектировщик БД, Дизайнер интерфейса,
   Проектировщик бэкенда, Автор тестов, Исполнитель, Помощник. Поддерживаются агенты Claude Code Pro
   и OpenCode Go Plus.

## Код

`studio/pipeline/` — ядро конвейера: `kinds` (виды записей и родители), `bank`, `coverage`
(проверки кодом), `gates` (каталог ворот и критерии по умолчанию), `keeper` (прогон ворот),
`changes` (запросы на изменение), `settings` (режим, критерии, роли), `roles`.
`studio/pipeline/graph/` — хранилище записей с журналом и отменой (бывший «Граф идеи»).

## План реализации

1. Ядро конвейера (готово): банк, статусы, связи, проверки, ворота, запросы, настройки, роли.
2. Этап 1 на ядре: шаги 1.1–1.8, агенты, экран.
3. Этап 2: словарь, варианты, сценарии, схемы БД, слияние, ER-карта.
4. Этапы 3–4 на машинерии студии: ТЗ из банка, тесты из критериев, реализация, замена моков.
5. Этап 5 и входы: запуск, итоговая приёмка, сканер «Развитие», быстрый путь.
6. Главный экран «Карта системы», настройки (режим, критерии ворот, роли агентов).
7. Уборка: удалить всё, чего нет на схеме (старые цепочки, автопилот-цикл, прототип product-chain).
