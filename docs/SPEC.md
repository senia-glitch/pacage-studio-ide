# pacage-studio: устройство пакета

## Что это

Офлайн-инструмент для проектов на `fastbase` / `core-package` / `event-infra`.
Сканер читает код по AST и строит граф:

```
endpoint → scenario → io → model
```

Существующий код не изменяется; создаются только новые файлы-скелеты.
Все описания, критерии, домены, связи и планы — в `.studio/metadata.json`.

## Блоки

1. **Чтение кода** (`studio/source.py`) — единственное место чтения исходников
   проекта. Ошибки кодировки/синтаксиса возвращаются диагностиками.
2. **Сканер** (`studio/scanner/`) — чистая функция «файлы → граф»: индексация
   endpoint/scenario/model, связи, тесты, nested-узлы, жёлтые пометки.
3. **Хранилище метаданных** (`studio/metadata/`) — чтение/запись
   `.studio/metadata.json`; к коду проекта не обращается.
4. **Создание** (`studio/creator/`) — один сценарий одной цепочкой слоёв:
   проверка ввода, файлы-скелеты endpoint/scenario/test с TODO и запись плана
   в метаданные. Всё или ничего.
5. **ТЗ** (`studio/agent/brief.py`) — граф, исходники и правила → markdown.
6. **Проверка ТЗ** (`studio/agent/verify.py`) — узел, связи, тест; только
   факты.
7. **UI** (`studio/ui/static/js/`) — карта, сценарий, инспектор, создание,
   диагностика, ТЗ; состояние — в localStorage.
8. **Сервер** (`studio/server/`) — stdlib HTTP, токен, live-обновление.
9. **Фронтенд** (`studio/frontend/`) — сканер `frontend/` (слои, DAG, нарушения),
   метаданные `.studio/frontend.json`, ТЗ, отчёт и синхронизация описаний.
10. **Отчёт по бэкенду** (`studio/agent/report.py`) — сводка, структура,
    покрытие, планы, модели и диагностика по графу; `studio report`, `/api/report`.
11. **JSON-ответ синхронизации** (`studio/agent/sync_json.py`) — разбор и проверка
    ответа агента; запись только по явному «Применить».
12. **Доступ агента** (`studio/server/access.py`) — производные токены режимов
    `plan` и `implement`, таблица разрешённых маршрутов, самоописание
    `GET /api/agent`; агент не применяет ответы и не пересобирает ТЗ. Сервер
    ставит `created_by: agent` на всё, что создал агент; второй счётчик `aux`
    (frontend.json, ideas.json) будит `/api/wait` для живого обновления.
13. **Связи фронтенд → бэкенд** (`studio/frontend/links.py`) — объявленные
    `calls` у страниц и блоков, сверка с эндпоинтами графа бэкенда (префикс API и
    параметры нормализуются); `links` в `/api/frontend/graph`, раздел ТЗ.
14. **Проверка ТЗ фронтенда** (`studio/frontend/verify.py`) — задачи ТЗ по маркеру
    `studio-front-brief` сверяются с кодом; `studio verify --part frontend`,
    `/api/frontend/verify`.

## Граф

Схема v7. Виды узлов: `endpoint`, `scenario`, `io`, `model`, `test`, `nested`.
Связи: `dispatch`, `scenario_call`, `port_call`, `table`, `tests`, `uses`,
`depends`. Узлы и рёбра могут иметь `notes` — причины жёлтой подсветки.
Узлы плана несут `plan` (slug) и `layer`; `Graph.plans` — состояния планов,
которые считает `resolve_plan`.

`nested` — один уровень: self-методы сценария, функции файла и импортированные
модули проекта. Внешние модули и stdlib не показываются.

## Планы сценариев

План — цепочка слоёв (endpoint, scenario, [io, model], [test]), описанная одним
текстом. Планы живут в `metadata.json` (версия 2). Скан создаёт планируемые
узлы endpoint/scenario/test, рёбра `dispatch` и `tests`, а `resolve_plan`
привязывает слои к коду и выставляет статус `done` / `partial` / `not_done`.

## Метаданные

Один файл `.studio/metadata.json`, ключ — стабильный якорь узла. Служебные
поля: `kind`, `name`, `file_path`, `target_file`, `details`. Пользовательские:
`description`, `acceptance`, `domain` (только endpoint), `planned`. Связи из
metadata.json для существующих узлов — только `uses`/`depends`.

## Диагностика

Коды `E_*` — ошибки, `W_*` — предупреждения и жёлтые пометки, `I_*` —
информация. Молчаливое отбрасывание узлов и связей запрещено.

## Интеграция

Только VS Code: `vscode://file/<path>:<line>`. Другие редакторы не
поддерживаются.
