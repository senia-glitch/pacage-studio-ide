# Как пользоваться студией

## Быстрый цикл

```powershell
studio doctor                  # проверить источники и окружение
studio                         # автоскан + интерфейс, открывает браузер
studio dev                     # то же явно: --host, --port, --no-open, --poll, --verbose
studio scan [--json]           # только скан → .studio/graph.json
studio list [--json]           # сценарии в терминале
studio brief [--stdout] [--plan SLUG] [--only ANCHOR] [--scenario NAME] [--section NAME]
studio verify [BRIEF] [--part backend|frontend]   # проверить выполнение ТЗ
studio report [--part backend|frontend] [--section NAME ...] [--stdout | --json]
studio skill [--target stdout|claude|agents|all]   # руководство для AI-агента
studio mcp                     # MCP-сервер для AI-агента (stdio), см. mcp.md
studio install-full            # fastbase[full] в текущий venv
studio help                    # все команды
studio --version               # версия пакета
```

Про ТЗ для AI-агента — в [agent-brief.md](agent-brief.md).

## Рабочие области

### Карта проекта

Карта показывает фактические узлы проекта и плановые узлы в одной структуре.
Переключатель **«Факт»** приглушает плановые узлы и плановые пометки изменений;
**«План»** приглушает фактические узлы. HTTP-методы и домены отображаются как
группы. Домены можно добавить в план или предложить переименовать; до реализации
код и фактические данные не меняются.

Нажмите на карточку, чтобы открыть её свойства в правой панели. У фактического
узла можно записать заметку о будущей правке и критерии приёмки. У планового
узла можно менять название, описание и критерии. Наведите курсор на карточку и
нажмите **＋**, чтобы добавить потомка. Типы узлов зависят от типа родителя;
плановую ветку можно удалить целиком, фактический код при этом сохраняется.
Правую панель можно скрыть или изменить её ширину перетаскиванием разделителя.
Карта автоматически располагает карточки без наложений.
Перетаскивайте карточку за любую свободную область: её потомки двигаются
вместе, а у соседних карточек ветка скользит вдоль края без пересечения.

У каждого эндпойнта своя компактная ветка, которая раскрывается сверху вниз.
Если несколько эндпойнтов используют один узел, карта показывает его копию в
каждой соответствующей ветке. Это один узел в плане: выбор любой копии
подсвечивает остальные, а редактирование и добавление потомков применяются ко
всем отображениям.

Поиск (`/`) фильтрует карту по имени, URL, домену и описанию. Используйте
**«Обновить код»**, чтобы перечитать проект после изменений в IDE. Структуру
фактических узлов меняйте в IDE; карта сканирует код и хранит планы отдельно в
`.studio/metadata.json`.

### Генератор идей

Создайте узел идеи и опишите задачу. Кнопка **«Собрать промпт»** готовит
промпт с контекстом проекта; `studio` не вызывает LLM. Скопируйте промпт,
обсудите его с LLM и вставьте ответ JSON в корневой узел. Общий поиск в шапке
фильтрует доску по названию идеи, описанию, названию сценария и домену. Кнопка
**«Разобрать сценарии»** создаст карточки-сценарии в связанной ветке.

Если задача затрагивает интерфейс, промпт просит у LLM ещё и ключ `pages` —
страницы и блоки фронтенда (папка, маршрут, роль, вызываемые эндпоинты).
**«Разобрать ответ»** принимает ответ целиком: JSON можно оставить внутри
```-блока и среди текста. Сценарии бэкенда и страницы фронтенда появляются двумя
ветками (переключатель **«Бэкенд | Фронтенд»** над веткой); **«Во фронтенд ↗»**
создаёт плановую страницу и блоки во вкладке «Фронтенд» (повторная передача
обновляет те же узлы) и сообщает, каких эндпоинтов ещё нет в бэкенде.

Карточки можно править и явно передавать сценарии в план общей карты. Удаление
карточки удаляет её сценарий из JSON идеи. Доска идей (идеи, промпты и ветки)
хранится в проекте — `.studio/ideas.json` — и переносится вместе с ним.
**«Экспорт»** и **«Импорт»** делают резервную копию доски и восстанавливают её.

### Отчёт по проекту

Кнопка **«Отчёт»** на верхней панели карты и команда `studio report` собирают
отчёт о том, что уже есть в проекте (а не задачи на будущее — это ТЗ). Разделы
включаются флажками, порядок у них фиксированный:

- **Сводка** — число эндпоинтов, сценариев, io, моделей и тестов (с плановыми),
  домены и планы;
- **Структура** — домен → HTTP-метод → эндпоинт → сценарий → io → модель, тесты;
- **Покрытие** — сколько узлов с описанием, критериями и тестом, и список узлов
  без описания;
- **Планы** — статус каждого плана и его слоёв;
- **Модели** — таблицы, число полей и сценарии, которые в них пишут;
- **Диагностика** — предупреждения скана и жёлтые пометки.

В окне отчёта текст можно править (копирование и скачивание берут ваш
вариант), «Скачать .json» отдаёт те же сведения структурно. Файл —
`.studio/report.md`. Команда: `studio report` пишет файл, `--stdout` печатает
markdown, `--json` — `{path, markdown, data}`, `--section summary --section
models` выбирает разделы, `--part frontend` — отчёт по `frontend/`
(`.studio/frontend-report.md`). Неизвестный раздел — ошибка (код возврата 2).

### Фронтенд

Вкладка «Фронтенд» читает `frontend/` проекта (Vue 3 + Pinia + Router + Vite):
карта страниц и блоков по слоям `ui/…` → `logic/…`, правила DAG и UI-стандарта,
нарушения с `файл:строка`. Описания, критерии, домены (роли) и правила страниц
и блоков хранятся в `.studio/frontend.json`; код `frontend/` студия не меняет.

- **⇄ ТЗ…** — ТЗ для AI-агента: область (выбранный узел и потомки / весь
  фронтенд / только нарушения) и разделы «Область работ», «Связи с бэкендом»,
  «Нарушения», «Проверка» выбираются в окне; текст можно править прямо там — «Скопировать»
  и «Скачать» берут ваш вариант, файл `.studio/agent-brief-frontend.md`
  хранит исходный.
- **Проверить ТЗ** — сверяет последнее ТЗ фронтенда с кодом `frontend/`:
  плановые страницы и блоки появились, убираемые — исчезли, объявленные вызовы
  эндпоинтов находят эндпоинт в бэкенде. Правила код проверить не может — их
  отмечаете вы («Реализовано»). То же из терминала: `studio verify --part frontend`.
- **Отчёт** — инвентаризация фронтенда; разделы (стек и сводка, замечания
  проекта, структура, покрытие правил, нарушения, связи импортов) включаются
  флажками; «Скачать .json» отдаёт те же сведения структурно.
- **⇄ Синхр. описаний** — см. следующий раздел.
- **Связи с бэкендом.** В свойствах страницы и блока — поле «Вызывает эндпоинты
  бэкенда» (по одному `МЕТОД /путь` на строку, префикс API можно не писать).
  Студия сверяет вызовы с эндпоинтами бэкенда, фактическими и плановыми, и
  показывает ✓ или ✗; недостающие эндпоинты попадают в ТЗ (раздел «Связи с
  бэкендом»). Сканер кода вызовы не ищет: связи объявляете вы или агент в режиме
  планирования.

### Синхронизация описаний с кодом

Кнопка «⇄ Синхр. описаний» на верхней панели карты и на вкладке «Фронтенд»
открывают диалог из двух шагов:

1. **Промпт.** Выберите область (весь проект / домен / страница / узлы без
   описания), скопируйте промпт и отдайте AI-агенту с доступом к папке проекта.
   Агент читает код и отвечает одним JSON-блоком; файлы он не правит.
2. **Принять ответ.** Вставьте ответ агента (можно целиком, вместе с текстом
   вокруг блока `json`) и нажмите «Проверить»: студия покажет по каждой записи,
   что изменится, а что отклонено и почему. «Применить выбранные» записывает в
   метаданные только отмеченные записи — и только `description` и `acceptance`.

Формат ответа — в [agent-brief.md](agent-brief.md).

После «Применить» рядом с итогом появляется **«↩ Отменить применение»**: он
возвращает прежние описания и критерии. Узел, который вы успели изменить уже
после применения, отмена не трогает — студия пишет, сколько узлов пропущено.

То же окно «Принять…» есть у ТЗ: итоговый отчёт агента по ТЗ — строгий JSON.
В окне ТЗ откройте вкладку «Принять отчёт агента», вставьте ответ — студия
сверит записи с кодом, покажет отличия и блок «Отчёт агента» (тесты, решения,
вопросы), а описания и критерии реализованных узлов запишет только по «Применить».

### Подключение AI-агента

Кнопка **«AI-агент»** в шапке открывает окно с режимом и строкой подключения
(адрес студии, токен, режим; для режима «реализация» показано, собрано ли ТЗ). Скопируйте её и вставьте агенту — токен он не
сохраняет, а при следующем запуске студии токен новый.

- **Планирование.** Агент читает проект и предлагает идеи и плановые узлы; вы
  видите их в интерфейсе и решаете, что реализовывать. Код он не пишет.
- **Реализация.** Отметьте задачи чекбоксами в окне «ТЗ» и нажмите «Сохранить в
  проект». Агент заберёт именно это ТЗ (`studio_brief`), реализует его и проверит
  (`studio_verify`). Итоговый отчёт агент отправит сам (`studio_report`): в шапке
  появится кнопка **✉ N**. Откройте отчёт,
  проверьте отличия и нажмите «Применить» — пока вы этого не сделали, ничего не
  записано. Вручную отчёт тоже можно вставить во вкладке «Принять отчёт агента».

Агент работает со студией только через MCP-сервер `studio mcp` (extra
`pacage-studio[mcp]`): инструменты `studio_connect`, `studio_idea_add`, `studio_brief`,
`studio_verify`, `studio_report` и другие. Подключение — той же строкой из окна «AI-агент»;
настройка клиента и список инструментов — в [mcp.md](mcp.md).

Порядок работы агенту описывает руководство ([agent-workflow.md](agent-workflow.md)): MCP-сервер
отдаёт его клиенту при подключении, а `studio skill --target claude` (скилл Claude Code),
`--target agents` (блок в `AGENTS.md`) или `--target all` устанавливает его в проект;
`studio skill` без флагов печатает текст. Повторный запуск обновляет файлы после обновления
пакета.

Ограничения режимов сервер проверяет сам: агент не может применять ответы
(`apply`), пересобирать ТЗ, создавать файлы-скелеты и править описания
существующих узлов.

Всё, что создал агент, помечено бейджем **«агент»** (карта, дерево, свойства,
вкладки «Фронтенд» и «Идеи»): сразу видно, что предложено им, а что вами; ненужное
удаляется как обычный узел. Вкладки «Фронтенд» и «Идеи» обновляются сами, пока
агент работает; если вы в этот момент вводите текст, перерисовка ждёт, пока вы
закончите.

Доска идей хранит `revision`: если вы и агент правите её одновременно, устаревшая
запись отклоняется, а интерфейс загружает актуальную версию.

## Метаданные

Описания, критерии, домены, дополнительные связи и планируемые узлы хранятся
только в `.studio/metadata.json`. Формат — в
[metadata-format.md](metadata-format.md).

## Сохранение состояния

Раскладка, зум, выбранная вкладка и узел, ширина правой панели и переключатели
карты переживают F5: состояние интерфейса лежит в localStorage браузера.
Доска идей — не интерфейсное состояние, она лежит в `.studio/ideas.json`.

## Диагностика

Бейдж **⚠ N** открывает панель с группировкой по уровню и фильтром по коду и
тексту. Жёлтые пометки помечены как «неточность». «Копировать всё» отдаёт
markdown-список. Коды — в [troubleshooting.md](troubleshooting.md).

## Лог

`.studio/studio.log` — журнал сканов, ошибок и записи. HTTP-запросы по
умолчанию не пишутся; `studio dev --verbose` добавляет их. Удаление `.studio/`
стирает `metadata.json` безвозвратно: граф пересоберётся, описания — нет.
Поэтому `.studio/metadata.json` по умолчанию не игнорируется в git и
коммитится вместе с проектом; игнорируются только `graph.json`, `studio.log`,
`agent-brief.md`, `briefs/` и `last-brief.json`.
