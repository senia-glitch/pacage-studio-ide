# MCP-сервер студии

`studio mcp` запускает MCP-сервер (Model Context Protocol, stdio): AI-агент работает со
студией через готовые инструменты, а не через «сырой» HTTP. Сервер ничего не решает сам: он
подключается к уже запущенной студии и пересылает вызовы в её API с токеном вашего режима.
Права, правило владения («агент правит только своё»), журнал и входящие отчёты остаются на
стороне студии, поэтому запрещённое действие вернёт отказ студии — обойти его через MCP нельзя.

## Установка

MCP-сервер — необязательная часть пакета (нужна библиотека `mcp`):

```powershell
python -m pip install "pacage-studio[mcp] @ git+https://github.com/senia-glitch/pacage-studio-ide.git"
```

Без `[mcp]` остальные команды студии работают как раньше, а `studio mcp` подскажет, что
доустановить.

## Подключение клиента

Клиент (Claude Code, Claude Desktop и другие MCP-клиенты) запускает сервер как
процесс. Пример для Claude Code:

```powershell
claude mcp add pacage-studio -- studio mcp
```

Универсальная настройка (JSON клиента, ключ `mcpServers`):

```json
{"mcpServers": {"pacage-studio": {"command": "studio", "args": ["mcp"]}}}
```

Если `studio` не в `PATH` (например, он только в venv проекта), укажите команду целиком:
`"command": "<путь к venv>/Scripts/python.exe", "args": ["-m", "studio", "mcp"]`.

В настройке **нет** адреса и токена: токен меняется при каждом запуске студии и не должен
лежать в конфигах.

## Как работает

1. Запустите `studio` в проекте и нажмите **«AI-агент»**: выберите режим и скопируйте
   строку подключения (адрес, токен, режим).
2. Вставьте строку агенту. Он вызовет `studio_connect` — и дальше работает инструментами.
   Токен хранится только в памяти процесса MCP; после перезапуска студии нужна новая строка.
3. Режим определяет токен: `plan` (планирование) или `implement` (реализация). Инструкции с
   порядком работы MCP-клиент получает автоматически при подключении.

Подключаться можно только к локальной студии (`127.0.0.1`, `localhost`): токен и данные проекта
не уходят на чужой адрес. Для нестандартной схемы есть переменная окружения
`STUDIO_ALLOW_REMOTE=1` — используйте её осознанно.

## Инструменты

| Инструмент | Что делает | Режим |
|---|---|---|
| `studio_connect` | подключиться по строке из окна «AI-агент» (или `url` + `token`) | любой |
| `studio_overview` | корень, счётчики узлов, ревизия, число ждущих отчётов | любой |
| `studio_graph`, `studio_node` | узлы бэкенда в сжатом виде с фильтрами; один узел со связями | любой |
| `studio_frontend` | страницы, блоки, вызываемые эндпоинты и их статус в бэкенде | любой |
| `studio_ideas` | доска идей и её ревизия | любой |
| `studio_idea_add` | добавить идею (сценарии бэкенда и страницы фронтенда) | planning |
| `studio_node_add`, `studio_node_delete` | плановый узел бэкенда; удалить свой | planning |
| `studio_page_add`, `studio_block_add`, `studio_rule_add`, `studio_front_delete` | плановые страницы, блоки, правила фронтенда; удалить свои | planning |
| `studio_brief` | ТЗ, которое сохранил (бэкенд) или собрал (фронтенд) человек | implement |
| `studio_verify` | проверить по коду, выполнено ли ТЗ, и что осталось | implement |
| `studio_report`, `studio_reports` | отправить итоговый отчёт человеку; статусы отчётов | implement |

Идея, которую добавляет агент, попадает на доску; человек сам нажимает «Разобрать ответ» и решает,
что отправить на карту. Отчёт попадает в «Отчёты агента» (кнопка ✉) и применяется только по вашему
«Применить».

## Если что-то не работает

| Сообщение | Причина | Что делать |
|---|---|---|
| `not_connected` | агент не вызвал `studio_connect` | дайте агенту строку подключения |
| `bad_token` | студию перезапустили (токен новый) | скопируйте новую строку из окна «AI-агент» |
| `unreachable` | студия не запущена или адрес не тот | запустите `studio`, проверьте порт в строке |
| `bad_url` | адрес не локальный | студия слушает только `127.0.0.1` |
| `mode_forbidden` | режим не разрешает действие или это узел, идея, страница человека | запрещено намеренно: агент предлагает своё рядом |
| `ideas_conflict` | доску идей изменили одновременно | `studio_idea_add` сам повторяет со свежей доской; иначе перечитайте `studio_ideas` |

Что делал агент, видно в `.studio/studio.log` (строки `агент[plan] POST …`, `ЗАПРЕЩЕНО …`).
Руководство для агентов без MCP — [agent-workflow.md](agent-workflow.md) (HTTP).
