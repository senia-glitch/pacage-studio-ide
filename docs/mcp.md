# MCP-сервер студии

`studio mcp` запускает MCP-сервер (Model Context Protocol, stdio) — единственный интерфейс
AI-агента к студии: агент работает готовыми инструментами `studio_*`. Сервер ничего не решает
сам: он находит уже запущенную студию проекта и передаёт ей вызовы с токеном нужного режима.
Права, этапы дорожной карты и журнал остаются на стороне студии, поэтому запрещённое действие
вернёт отказ студии — обойти его через MCP нельзя.

## Установка

MCP-сервер — необязательная часть пакета (нужна библиотека `mcp`):

```powershell
python -m pip install "pacage-studio[mcp] @ git+https://github.com/senia-glitch/pacage-studio-ide.git"
```

Без `[mcp]` остальные команды студии работают как раньше, а `studio mcp` подскажет, что
доустановить. Нужен Python 3.12 или новее.

## Подключение клиента (один раз)

Клиент (Claude Code, Claude Desktop и другие MCP-клиенты) запускает сервер как процесс.
Пример для Claude Code:

```powershell
claude mcp add pacage-studio -- studio mcp
```

Универсальная настройка (JSON клиента, ключ `mcpServers`):

```json
{"mcpServers": {"pacage-studio": {"command": "studio", "args": ["mcp"]}}}
```

Если `studio` не в `PATH` (например, он только в venv проекта), укажите команду целиком:
`"command": "<путь к venv>/Scripts/python.exe", "args": ["-m", "studio", "mcp"]`.

В настройке **нет** адреса и токена: студия сама сообщает, где она запущена.

## Как агент находит студию

1. `studio` при старте пишет `.studio/server.json`: адрес и токены режимов `plan` и
   `implement` (корневой токен интерфейса туда не попадает). Файл исключён из git через
   `.studio/.gitignore` и удаляется при остановке студии.
2. `studio_connect()` без параметров ищет этот файл от папки проекта вверх. Клиенты
   запускают MCP-сервер в папке проекта; если нет — задайте переменную `STUDIO_PROJECT`
   или запустите `studio mcp --project <папка>`.
3. После перезапуска студии токены новые: клиент сам перечитывает файл и повторяет запрос.
4. Запасной путь: строка из окна «AI-агент» (адрес, токен, режим) —
   `studio_connect(connection=…)`. Нужна только если автоподключение невозможно.

Подключаться можно только к локальной студии (`127.0.0.1`, `localhost`): токен и данные
проекта не уходят на чужой адрес. Для нестандартной схемы есть переменная окружения
`STUDIO_ALLOW_REMOTE=1` — используйте её осознанно.

## Цикл агента

Агент вызывает `studio_workflow` и действует по полю `action`:

| action | этап дорожной карты | что делает агент |
|---|---|---|
| `wait` | человек выбирает режим, валидирует, переносит, выбирает задачи, читает отчёт | вызывает `studio_workflow` снова (сам ждёт до 25 с) |
| `propose` | «Идеи агента» | изучает проект, шлёт `studio_idea_add`, затем `studio_ideas_ready` |
| `implement` | «Реализация» | `studio_brief` → код → `studio_verify` → `studio_report` |

Запись вне своего этапа студия отклоняет (`stage_forbidden`).

**Автозапуск.** Если человек включил «⚙ Автозапуск», студия сама запускает агента на этапах
`propose` и `implement`; запущенный студией агент выполняет только текущий этап и завершается
(не опрашивает `studio_workflow` в цикле). Подробности — в [usage.md](usage.md).

## Инструменты

| Инструмент | Что делает | Этап |
|---|---|---|
| `studio_connect` | подключиться (без параметров — автообнаружение) | любой |
| `studio_workflow` | этап, задача человека, что делать сейчас; долгий опрос | любой |
| `studio_overview` | корень, счётчики узлов, ревизия, число ждущих отчётов | любой |
| `studio_graph`, `studio_node` | узлы бэкенда в сжатом виде с фильтрами; один узел со связями (у страницы и блока — `calls` и `calls_in_code`, найденные в коде) | любой |
| `studio_frontend` | страницы, блоки, вызываемые эндпоинты и их статус в бэкенде | любой |
| `studio_ideas` | доска идей и её ревизия | любой |
| `studio_idea_add` | идея со сценариями и страницами: каждый становится карточкой для свайпа | идеи, валидация |
| `studio_idea_withdraw` | отозвать свою идею (пока по ней нет принятых карточек) | идеи, валидация |
| `studio_ideas_ready` | идеи готовы: человек переходит к валидации | идеи |
| `studio_brief` | ТЗ по частям: без параметров — оглавление, `task=N` — одна задача, `section="2"` — раздел, `offset` — продолжение | реализация |
| `studio_verify` | проверка по структуре кода: выполнено ли ТЗ и что осталось (поведение подтверждают тесты) | реализация |
| `studio_tests` | итог независимого прогона тестов проекта студией и планы с упавшими тестами | любой |
| `studio_doctor` | диагностика проекта, как `studio doctor [--strict]`; новые и давние предупреждения (`new`, `ok_for_changes`) | реализация |
| `studio_report` | человекопонятный итог (`summary`) и необязательные описания узлов | реализация, отчёт |
| `studio_reports` | статусы ваших отчётов | любой |

Идея, которую присылает агент, попадает на доску уже разобранной: человек свайпает карточки,
а перенос на карту и выбор задач делает сам. Описания из `updates` отчёта записываются только
по «Применить» человека.

## Если что-то не работает

| Сообщение | Причина | Что делать |
|---|---|---|
| `not_connected` | агент не вызвал `studio_connect` | вызвать `studio_connect()` |
| `studio_not_running` | нет `.studio/server.json`: студия не запущена или сервер стартовал не из проекта | запустить `studio`; задать `STUDIO_PROJECT` |
| `bad_token` | студию перезапустили, файл ещё не обновился | вызвать `studio_connect()` снова |
| `unreachable` | студия остановлена или адрес не тот | запустить `studio` |
| `bad_url` | адрес не локальный | студия слушает только `127.0.0.1` |
| `stage_forbidden` | запись не подходит этапу дорожной карты | ждать этап: `studio_workflow` |
| `mode_forbidden` | действие только для человека (решения, перенос, выбор) или чужие данные | запрещено намеренно |
| `invalid_input` у `studio_idea_add` | плохой slug, нет описания, занятое имя | исправить сценарий и отправить заново |
| `ideas_conflict` | доску идей изменили одновременно | перечитать `studio_ideas` |

Что делал агент, видно в `.studio/studio.log` (строки `агент[plan] POST …`, `ЗАПРЕЩЕНО …`).
Руководство для агента — [agent-workflow.md](agent-workflow.md): сервер отдаёт его клиенту при
подключении, а `studio skill` устанавливает в проект (скилл Claude Code или `AGENTS.md`).
