# Прототип цепочки в OpenCode (шаги 1-8)

Роли и скиллы для OpenCode, которыми можно прогнать реальные идеи **до** встраивания цепочки в интерфейс
студии. Задача прототипа — выяснить, где качество проседает, и выправить промпты, пока это дёшево.

Роль студии в прототипе играет агент-дирижёр `chain`, механические проверки — команда `studio chain check`.
Шаги 9-11 (фронтенд на моках и тесты) сюда не входят: их делаем следующим этапом.

## Состав

Агенты и скиллы поставляются вместе с пакетом (`studio/productchain/assets/opencode/`).

| Агент | Режим | Шаги | Скиллы |
| --- | --- | --- | --- |
| `chain` | primary | дирижёр: порядок шагов, `chain.json`, точки решения | `chain-formats` |
| `researcher` | subagent | 1, 2 | `domain-framing`, `needs-research`, `competitor-analysis`, `norms-research` |
| `analyst` | subagent | 3, 5, исправления на 6-7 | `needs-map`, `justified-requirement` |
| `product` | subagent | 4 | `product-statement` |
| `critic` | subagent | 6 | `critique-checklist` |
| `reviewer` | subagent | 7 | `consistency-checklist` |
| `decider` | subagent | 1, 3, 4, 8 в авто-режиме | `decision-making` |

Каждой роли разрешены только её скиллы (и общий `chain-formats`); ролям запрещены shell и запуск других
агентов. Дирижёр может запускать только эти шесть ролей, а из команд терминала без вопроса — только
`studio chain …`. Права записаны в формате OpenCode 1.x (`permission:` с ключами `bash`, `task`, `skill`):
его понимает и OpenCode 1.x, и V2 (переводит сам).

## Установка

```powershell
studio chain install                  # в .opencode/ текущего проекта
studio chain install --dest "$HOME\.config\opencode"  # глобально, во всех папках
```

Повторная установка не трогает файлы, которые вы поправили вручную (они будут «пропущены»); `--force`
перезапишет их поставляемой версией.

## Запуск

1. Создайте папку под идею (или откройте проект) и установите роли, если ставили не глобально.
2. По желанию раскомментируйте в `agents/*.md` строку `model:` и укажите модель (`opencode models` покажет
   доступные); без неё роль работает на модели OpenCode по умолчанию. Исследователю и Решающему нужен
   веб-поиск; критику лучше другую модель, чем аналитику.
3. Запустите `opencode` в этой папке, переключитесь на агента `chain` (Tab) и напишите сырую идею, например
   «сайт для автосервиса».
4. Дирижёр спросит настройки (кто решает на шагах 1, 3, 4, 8 и сколько повторов). Можно ответить «по умолчанию».
5. Результаты появятся в `.studio/chain/`. Прерванную цепочку дирижёр продолжит с места остановки.

Команды, которые использует дирижёр (можно запускать и вручную):

```powershell
studio chain check            # механические проверки, коды выхода 0 / 1 / 2
studio chain check --json
studio chain merge-research 3 # влить черновики исследования прогона 3
studio chain summary          # сколько объектов в каждом файле
```

## Протокол оценки

Прогоните **2-3 разные идеи** (лучше из разных доменов) и для каждой заполните таблицу. Цель — понять, какую
роль или скилл править первым.

| Что проверить | Как | Норма |
| --- | --- | --- |
| Ссылки настоящие | откройте 10 случайных `sources` | 10 из 10 открываются и подтверждают факт |
| Факты не выдуманы | сверьте 10 фактов с их источниками | ≥ 9 из 10 |
| Конкуренты реальные и релевантные | просмотрите `competitors` | все существуют, ≥ 5 по делу |
| Потребности — не функции | прочитайте `needs.json` | ни одна не называет решение |
| Формулировка опирается на потребности | сравните `product.json` с `needs.json` | отличие от сырой идеи объяснено данными |
| У требований конкретная польза | прочитайте 15 случайных `items` | нет «удобно», критерии проверяемы |
| «Обязательно» и «предлагаем» разделены честно | просмотрите оба списка | вы согласны с ≥ 80 % |
| Критик находит реальные проблемы | прочитайте `remarks.json` шага 6 | ≥ 70 % замечаний по делу |
| Продукт цельный | пройдите 2 `journeys` глазами | путь проходит без дыр |
| Решающий решает как вы | сравните `decisions.json` со своим выбором | совпадение ≥ 80 %, расхождения объяснимы |
| Цена | число прогонов в `chain.json`, токены в OpenCode | запишите для сравнения |

Запишите 3 главные проблемы каждого прогона и роль, которая за них отвечает. Повторяющаяся проблема в разных
идеях — повод править скилл этой роли.

## Что известно заранее

- **Идентификаторы.** В студии номера будет выдавать сама студия. В прототипе роли нумеруют объекты сами,
  а проверка ловит дубли; параллельные черновики исследования перенумеровывает `merge-research`.
- **Критик не исправляет.** Шаг 6 даёт исправленный список так: критик пишет замечания, аналитик исправляет.
  Так критик остаётся независимым от своих исправлений.
- **Синонимы словаря** проверка ищет по основе слова («заявка» найдёт «заявки»); сравнение грубое, возможны
  ложные срабатывания на коротких словах.
- **Права в OpenCode** записаны в формате 1.x: V2 читает его, но помечает устаревшим. После перехода на V2
  их стоит перевести в `permissions: [{action, resource, effect}]` (`bash` → `shell`, `task` → `subagent`).
