# Документация по AI-агентам и их скиллам

Новая цепочка студии «Продукт → Фронтенд»: от сырой идеи через анализ предметной области, конкурентов и норм
к обоснованным требованиям и принятому фронтенду на моках. Работу ведёт команда ролей-агентов, каждая со своими
скиллами; бэкенд строится отдельной цепочкой по контракту принятого фронтенда.

Сейчас (7.5) цепочка существует как **прототип в OpenCode** для шагов 1-8: роли и скиллы поставляются с пакетом,
ставятся командой `studio chain install`, а артефакты проверяет `studio chain check`. Встраивание в интерфейс
студии и шаги фронтенда — следующие этапы.

| Документ | О чём |
| --- | --- |
| [spec.md](spec.md) | спецификация: принципы, 11 шагов, роли, скиллы, настройки, Решающий, ревью согласованности, фронтенд на моках |
| [formats.md](formats.md) | JSON-форматы всех артефактов `.studio/chain/` и механические проверки |
| [prototype.md](prototype.md) | прототип в OpenCode: состав, установка, запуск, протокол оценки прогонов |

## Как это устроено

- **Роль = агент OpenCode** (`agents/<имя>.md`): свой промпт, модель, права и чистый контекст. Независимость
  критика и Решающего обеспечивается именно отдельным агентом.
- **Скилл = метод работы** (`skills/<имя>/SKILL.md`): как делать задачу. Роль загружает только разрешённые ей
  скиллы.
- **Дирижёр = студия.** В прототипе её работу делает агент `chain`: запускает роли, ведёт состояние, спрашивает
  вас на точках решения.

## Дальнейшие шаги

1. Прогнать 2-3 реальные идеи по протоколу оценки и поправить скиллы ролей, которые проседают.
2. Встроить шаги в студию: этапы вместо текущих, права ролей по этапам, MCP-инструменты для артефактов, экраны
   шагов, настройки, журнал решений.
3. Фронтенд на моках: контракт данных, слой моков, тест агентом, ваш тест по чек-листу (шаги 9-11).
4. Переход со старой цепочки для существующих проектов.
5. Цепочка «Бэкенд».
