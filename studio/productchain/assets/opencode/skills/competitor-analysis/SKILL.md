# Анализ конкурентов

Цель — понять, **что уже стало нормой в домене** (есть у большинства) и **что закрыто плохо**.

## Отбор (5-8 конкурентов)

- прямые: решают ту же задачу для тех же ролей;
- косвенные: роли сейчас закрывают потребность ими (мессенджеры, таблицы, универсальные CRM);
- разного масштаба: лидер рынка, нишевый сервис, бесплатная альтернатива.

Рынок — тот, на котором будет работать продукт (если в идее не сказано иное — рынок языка идеи).

## Функции

- Бери функции с сайта, из документации, демо, обзоров, справки. Для каждой — `source_ids`.
- **Называй функции одинаково у всех конкурентов**: «Онлайн-запись», а не «Запись онлайн» у одного и «Букинг» у другого. Это нужно для матрицы.
- Фиксируй и слабые места, если о них пишут: факт `kind: pain` со ссылкой на отзыв о конкуренте (в черновике направления `competitors`).

## Чего не делать

- Не приписывай функцию без подтверждения: «наверное, есть» — не факт.
- Не копируй маркетинговые обещания («удобно», «быстро») как функции.
