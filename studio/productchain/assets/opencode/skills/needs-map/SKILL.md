# Карта потребностей

Потребность — **что роль хочет получить**, сформулированное без решения.

- Хорошо: «Записаться на ремонт без звонка, в том числе в нерабочее время».
- Плохо: «Онлайн-виджет записи» (это решение), «Удобство» (слишком общо).

## Как сводить

1. Сгруппируй факты, которые говорят об одном и том же для одной роли. Одна группа → одна потребность.
2. Сформулируй `statement` от лица роли, конкретно и проверяемо.
3. Укажи все `fact_ids`, на которых она держится. Потребность без фактов не существует.
4. Нормы (`fact.kind = norm`) становятся потребностями с `required_by_norm: true`.

## Оценки

- `frequency`: как часто встречается в фактах (`high` — массово, `low` — единично).
- `severity`: насколько больно, если не закрыто (`high` — теряют деньги, клиентов, время, нарушают закон).
- `coverage`: насколько хорошо закрывают конкуренты (`none` — никто, `full` — почти все и хорошо); `covered_by` — кто.
- `rank`: сначала нормы, затем по формуле «острота × частота», при равенстве выше та, что хуже закрыта конкурентами.

## Признаки ошибки

- Две потребности различаются только словами — объедини.
- Потребность держится на одном факте `low` — оставь, но с `frequency: low`, не раздувай.
- В формулировке есть название функции — переформулируй.
