# Studio — как запустить и работать

Практическая инструкция: команды, вкладки, метаданные и типовые ошибки.

`pacage-studio` — офлайн-карта пути HTTP-запроса:

```
endpoint (fastbase) → scenario (core-package) → io → model (event-infra)
```

Сканер читает код по AST и не запускает проект. Пакет создаёт и изменяет
только свои метаданные — комментарии с меткой `studio`.

---

## 1. Проверка перед стартом

```powershell
studio help
```

Должны быть команды `dev`, `scan`, `list`, `help`. Если `studio` не найдена,
установите пакет в venv проекта:

```powershell
python -m pip install --upgrade --force-reinstall "pacage-studio @ git+https://github.com/senia-glitch/pacage-studio-ide.git"
```

Подробнее: [УСТАНОВКА.md](УСТАНОВКА.md).

## 2. Пробный проект

Создайте папку проекта:

```powershell
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\api\v1\routes"
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\scenarios"
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\tests"
```

Файлы:

```powershell
Set-Content -Path "C:\Temp\opencode\myapp\.env.fastbase" -Value @'
FAT_ROUTES_PACKAGE=app.api.v1.routes
FAT_CORE_DISCOVER=app.scenarios
FAT_API_PREFIX=/api/v1
'@

Set-Content -Path "C:\Temp\opencode\myapp\models.py" -Value @'
from sqlmodel import SQLModel


class Order(SQLModel, table=True):
    __tablename__ = "orders"
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\api\v1\routes\views.py" -Value @'
from fastapi import APIRouter
from core import run

router = APIRouter(tags=["orders"])


# studio: description start
# Создаёт заказ.
# studio: description end
# studio: domain start
# orders
# studio: domain end
@router.post("/orders")
async def create_order(payload: dict):
    return await run("create_order", payload)
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\scenarios\orders.py" -Value @'
from core import BaseScenario, register_scenario


@register_scenario("create_order")
class CreateOrderScenario(BaseScenario):
    async def execute(self, dto):
        await self._db.create("orders", {})
'@

Set-Content -Path "C:\Temp\opencode\myapp\tests\test_orders.py" -Value @'
def test_create_order():
    assert True
'@
```

## 3. Первое сканирование

```powershell
studio --project "C:\Temp\opencode\myapp" scan
studio --project "C:\Temp\opencode\myapp" list
```

Ожидаемо:

| Команда | Результат |
|---|---|
| `scan` | `endpoints 1, scenarios 1, io 1, models 1, tests 1` |
| `list` | `endpoint POST /api/v1/orders`, `scenario create_order`, `io: _db.create(orders) -> Order` |

Появится `.studio/graph.json`, `.studio/studio.log` и `.studio/.gitignore`.
Код проекта `scan` не меняет.

## 4. Запуск интерфейса

```powershell
studio --project "C:\Temp\opencode\myapp"
```

или явно:

```powershell
studio --project "C:\Temp\opencode\myapp" dev
```

Откройте **http://127.0.0.1:8777**. При каждом запуске пакет автоматически
сканирует проект и только затем показывает интерфейс. Остановка — `Ctrl+C`.

## 5. Вкладки

### Карта

Перемещаемая область **fastbase**. Внутри — перемещаемые области по HTTP-методу,
в каждой лежат узлы-эндпоинты. Области автоматически подстраиваются под узлы;
узлы не выходят за границы своей области, узлы и области не пересекаются.
На узле видны только метод, URL и имя функции. Клик открывает вкладку
«Сценарий» для этого пути.

### Сценарий

Подробный путь одного сценария: `endpoint → scenario → io → model`, тесты —
отдельная область справа. Каждый слой — перемещаемая область с узлами; узлы
перетаскиваются за заголовок и не выходят за область. При пересечении движение
останавливается в последней допустимой точке, соседние области не сдвигаются.

Периферийные узлы (локальные модули, которые использует эндпоинт/сценарий) —
такие же карточки с drag-handle; они соединены с родителем пунктирным ребром,
двигаются вместе с ним и могут отдельно перемещаться внутри области.

Список сценариев слева разделён на зоны: сначала **HTTP-метод**, внутри —
**доменное имя** («без домена» — отдельная группа). В самом низу — раздел
**«Неполные»** со всеми узлами без любого пути до эндпоинта; они же показаны
в отдельной перемещаемой области канваса «неполные» (всегда, даже пустой).

Клик по узлу открывает форму метаданных:

- описание;
- критерии приёмки — по одному на строку;
- домен — редактируется только у эндпоинта, остальные узлы наследуют его
  автоматически (если эндпоинтов несколько, домены перечисляются через запятую).

Клик по пустому месту канваса или `Esc` снимает выделение с узла.
Правки сохраняются автоматически при потере фокуса и перезаписывают маркеры
в коде. Пустой раздел удаляется вместе с парой маркеров. Метаданные на узлах
можно визуально скрыть чекбоксом в шапке.

### Создание

Графический конструктор нового сценария. На канвасе — перемещаемые области
по видам узлов. У каждой области в заголовке есть кнопка `+`: она создаёт
пустой узел этого вида в свободном месте. Камера при добавлении не двигается;
названия областей и `+` масштабируются вместе с картой, но не выходят за
разумные пределы. HTTP-метод и путь эндпоинта необязательны. У поля
«Имя / якорь» есть всплывающая подсказка: это имя элемента кода, к которому
привяжутся метаданные, когда код появится.

Узлы и области перетаскиваются по тем же правилам: без выхода за границы и без
пересечений. Связь создаётся перетаскиванием от точки справа от узла к другому
узлу; тип связи подставляется по видам узлов, его можно изменить в панели
«Связи», там же связь удаляется.

По кнопке «Создать» генерируются **только файлы с метаданными**, по одному на
узел. В каждом файле есть пометка, что имя/якорь — желаемое и его можно
изменить при написании кода. Код не генерируется. Существующие файлы не
перезаписываются. Полей выбора таблиц БД нет: реализации ещё нет.

## 6. Метаданные в коде

Блоки ставятся над якорем:

- endpoint — над декоратором функции;
- scenario / model — над декоратором/классом;
- test — над тест-функцией;
- io — над вызовом `self._db.<method>` в `execute`.

```python
# studio: description start
# Текст описания.
# studio: description end
# studio: acceptance start
# - критерий 1
# - критерий 2
# studio: acceptance end
# studio: domain start
# orders, billing
# studio: domain end
```

Связь:

```python
# studio: edge start
# from: create_order
# to: CreateOrderScenario
# kind: dispatch
# studio: edge end
```

Типы связей: `dispatch`, `scenario_call`, `port_call`, `table`, `tests`,
`uses`, `depends`.

Если якорь пропал, метаданные остаются в файле, но не показываются в UI.
При следующем явном сохранении метаданных файла через форму блоки-сироты
удаляются вместе с маркерами.

Если кода ещё нет, но есть файл-план с пометкой «Желаемое имя/якорь», узел
показывается с чипом «без кода». Когда код с тем же якорем появляется,
метаданные плана подмешиваются к код-узлу; приоритет у файла с кодом.

## 7. Повседневный цикл

```powershell
studio --project "<путь>" scan          # пересобрать граф после правок кода
studio --project "<путь>" dev           # открыть интерфейс (автоскан при старте)
studio --project "<путь>" list          # быстро посмотреть сценарии в терминале
studio --project "<путь>" export        # пересоздать STUDIO_METADATA.md
studio --project "<путь>" install-full  # установить/обновить fastbase[full]
```

`studio export` пишет в корень проекта `STUDIO_METADATA.md`: правила ручного
редактирования метаданных, полные сценарии по цепочке «домен → HTTP-метод →
эндпоинт → сценарий» и в конце — «Неполные узлы».

`studio install-full` запускает установку через текущий интерпретатор:
`python -m pip install --upgrade "fastbase[full] @ git+https://github.com/senia-glitch/fastapi-transport.git"`.

Маркеры в коде — источник истины при сканировании. Форма в UI при сохранении
перезаписывает маркеры и становится истиной.

## 8. Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| `studio` не найдена | Активируйте venv или вызывайте `python -m studio` |
| Порт занят при `dev` | Остановите прошлый `dev` (`Ctrl+C`) или укажите `--port 8778` |
| Пустой список сценариев | Проверьте `@register_scenario("<name>")` и `FAT_CORE_DISCOVER` |
| Нет io-узлов | В `execute` нет вызовов `self._db.<method>(...)` |
| Нет модели у io | Таблица не найдена: нужен SQLModel-класс с `__tablename__` в `models.py` |
| Описание не появилось | Маркеры должны стоять над якорем; после ручной правки выполните `studio scan` |
| Домен не сохраняется у сценария | Домен назначается только эндпоинту, остальные узлы наследуют его |
| Кракозябры в консоли | Отображение PowerShell; выполните `chcp 65001` |
| Нужны детали | Смотрите `.studio/studio.log` |
