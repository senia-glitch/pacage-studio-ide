# Studio — как запустить и работать (инструкция с нуля)

Здесь только практика: команды, куда нажимать, что должно получиться.
Про устройство пакета читать не нужно.

---

## 1. Проверка перед стартом (1 минута)

Открой PowerShell и выполни:

```powershell
studio help
```

Должен показаться список команд (`init`, `scan`, `validate`, `save`, `dev`, `help`).
Если команда не найдена — из папки пакета выполни:

```powershell
pip install -e .
```

`studio help` после этого обязана работать. Всё ниже запускается из **любого места** —
важен только флаг `--project`, указывающий на твой проект.

### Полный стек одной командой (необязательно)

По умолчанию studio ставится голым — только `pydantic`, чужих пакетов нет.
Чтобы вместе со studio приехал весь инфраструктурный стек
(`fastbase` + `core-package` + `event-infra`), ставь с флагом `[full]`:

```powershell
pip install "pacage-studio[full] @ git+https://github.com/senia-glitch/pacage-studio-ide.git"
```

или из папки пакета:

```powershell
pip install -e ".[full]"
```

Проверка: `fb version` должен ответить версией. Дальше стек поднимается
по его собственной инструкции (`fb init`, `infra-init`, `core-init`),
а studio используется как обычно — через `studio ...` из этой инструкции.

## 2. Подготовь пробный проект (копипаст, 2 минуты)

Демо-проект — обычная папка с кодом. Создай её командами ниже
(папка `C:\Temp\opencode\myapp`, пробелов в пути нет — так надёжнее):

```powershell
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\schemas"
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\scenarios"
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\api\v1\routes"
```

Положи три файла (контракт, реализация, представление) — в раскладке стека:

```powershell
Set-Content -Path "C:\Temp\opencode\myapp\app\schemas\contracts.py" -Value @'
from abc import ABC, abstractmethod


class OrderContract(ABC):
    @abstractmethod
    def create_order(self, payload: dict) -> dict: ...
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\scenarios\service.py" -Value @'
from core import BaseScenario, register_scenario


@register_scenario("create_order")
class CreateOrder(BaseScenario):
    async def execute(self, dto):
        return {"id": 1}
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\api\v1\routes\views.py" -Value @'
from fastapi import APIRouter


router = APIRouter()


def create_order(payload: dict) -> dict:
    return {"via": "views", "payload": payload}
'@
```

## 3. Инициализация и первое сканирование

```powershell
studio --project "C:\Temp\opencode\myapp" init
studio --project "C:\Temp\opencode\myapp" scan
studio --project "C:\Temp\opencode\myapp" validate
```

Что должно получиться:

| Команда    | Ожидаемый результат                                  |
|------------|------------------------------------------------------|
| `init`     | `created: ...\.studio\config.toml`                   |
| `scan`     | `scan: nodes 3, links 1, violations 0`                |
| `validate` | `ok: no clean-architecture violations`               |

Появилась папка `C:\Temp\opencode\myapp\.studio` — там `config.toml` (настройки),
`graph.json` (граф), `studio.log` (лог каждого запуска, перезаписывается).

## 5. Тур по интерфейсу (что нажимать)

**Шапка (сверху):** `File` (экспорт графа, сброс), `Scan`, `Save`, `Validate`,
`Показать изменения`, справа — `⚙ Конфигурация`.

**Канвас (центр):** прямоугольники — файлы, точки по бокам — контракты,
стрелки — связи. Шапка узла и колонка выкрашены в цвет пакета:
фиолет — `infra`, синь — `core`, оранж — `presentation`, серый — `shared`.
Колонка содержит только свой пакет — примесей не бывает.
- Перемещение: тяни **фон** канваса мышью (панорама), колесо — зум,
  кнопки `+`/`−`/`вписать`/`1:1` над канвасом, справа — текущий масштаб.
- Узел таскается за шапку (под текущим зумом), двойной клик — развернуть/свернуть.
  Узлы стоят на сетке и не могут лечь друг на друга.
- Клик по узлу подсвечивает его сквозную цепочку через все пакеты, остальное гаснет.
- В шапке всегда видно `● не сохранено`, если есть незаписанные правки.

**Палитра (слева):** пары «домен × слой». Перетащи любую на канвас —
создастся новый узел (файл появится только после `Save`).

**Инспектор (справа):** клик по узлу или стрелке — свойства, контракты,
кнопки удалить. Контракты правятся построчно: `имя — abs` или `имя — impl`.

**Аутлайнер (слева внизу):** дерево домен → слой → файлы. Клик — выбрать и показать.

**Режимы канваса** (кнопки над канвасом): `Вся система` (3 колонки пакетов + `shared`),
`Бизнес-домены` (сквозные колонки по смыслу: `заказ`, `пользователь`, …),
`Только нарушения`. Фильтров нет — структура видна сразу.

> Бизнес-домен берётся из папки сразу после `scenarios/` `routes/` `schemas/`
> (например, `app/scenarios/order/...` → `order`). Файлы в корне этих папок
> и `models.py` целиком попадают в колонку «общее».

**Code view:** кнопка `code` на узле — содержимое файла прямо на канвасе.
Правишь текст → кнопка `в буфер`. Файлы на диске при этом **не меняются**.

**Новая связь:** клик по точке контракта → клик по точке другого узла.
Запрещённую связь интерфейс не даст провести (подскажет тостом).

**Конфигурация (шестерёнка):** default-домен, слои (пути + маркеры содержимого),
regex именования, таблица разрешённых
стрелок, настройки `save`. `Сохранить в config.toml` — палитра и проверки
обновляются сразу. Если менял имена/правила — после этого нажми `Scan`
(граф перестроится по новым правилам, буфер правок при этом затрется —
интерфейс предупредит).

## 6. Сохранение изменений в код

**Вариант А — из интерфейса:** кнопка `Save`. Если включён показ diff или есть
нарушения — покажет изменения и спросит подтверждение.

**Вариант Б — из терминала** (интерфейс можно не открывать):

```powershell
# только посмотреть, что изменится (файлы не трогает):
studio --project "C:\Temp\opencode\myapp" save --diff-only

# записать:
studio --project "C:\Temp\opencode\myapp" save --yes
```

После `Save` граф перестраивается из нового кода автоматически.

## 7. Посмотри нарушение вживую (необязательно, 1 минута)

Добавь контракт инфраструктуры и его реализацию в представлении —
это запрещённая стрелка `representation → infrastructure`:

```powershell
Set-Content -Path "C:\Temp\opencode\myapp\models.py" -Value @'
from abc import ABC, abstractmethod


class Store(ABC):
    @abstractmethod
    def put(self, x: dict) -> dict: ...
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\api\v1\routes\views.py" -Value @'
from fastapi import APIRouter


router = APIRouter()


def create_order(payload: dict) -> dict:
    return {"via": "views", "payload": payload}


def put(x: dict) -> dict:
    return x
'@
```

```powershell
studio --project "C:\Temp\opencode\myapp" scan
studio --project "C:\Temp\opencode\myapp" validate
```

`validate` покажет 1 нарушение `representation → infrastructure`. В интерфейсе
(режим `только нарушения`) эта связь будет красной.

## 8. Повседневный цикл (шпаргалка)

```powershell
studio --project "<путь>" scan      # обновил граф по коду
studio --project "<путь>" dev       # открыл интерфейс, правишь граф
# ... в интерфейсе: Save ...
studio --project "<путь>" validate  # проверил архитектуру
```

Правило одно: **правишь граф — жмёшь Save, иначе файлы не изменятся.**

## 9. Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| `studio` не найдена | `pip install -e .` из папки пакета |
| `no graph: run studio scan first` | Сначала `studio --project ... scan` |
| Порт занят при `dev` | Другой `dev` уже висит; останови его (`Ctrl+C`) или смени порт: `studio --project ... dev --port 8778` |
| Пустой канвас | Нажми `Scan` в шапке; проверь, что в проекте есть `.py`-файлы |
| `scan` затёр мои правки | Так задумано: scan строит граф заново из кода. Правки сначала `Save`, потом `scan` |
| Красная связь | Нарушение архитектуры (подробности — `validate` или режим `только нарушения`). Запись это не блокирует |
| `save` отклонён с ошибкой синтаксиса | В буфере битый код (code view). Открой узел, исправь, повтори |
| Кракозябры в консоли вместо русских букв | Это только отображение PowerShell; файлы и лог в порядке. Лечится `chcp 65001` |
| Нужны детали для отладки | Открой `\.studio\studio.log` в проекте — там каждый шаг последнего запуска |

Закрытие: в окне с `dev` нажать `Ctrl+C`. Проект при работе studio
запускать не нужно — пакет работает только с кодом как с текстом.

## Четвёртый пакет: studio (IDE)

Связка выше — это продукт. А `studio` — инструмент разработчика для работы
с кодом этого продукта: офлайн-IDE, которая строит граф проекта по исходникам
(файл — узел, совпадение имён контрактов — связь), даёт править архитектуру
на графе и записывает правки обратно в код одной командой.

Принципы:

- Работает, пока проект **остановлен**. Рантайм не нужен: только чтение,
  отображение и запись файлов.
- Про связку `event-infra + core-package + fastbase` ничего не знает
  и знать не должна — видит только код как текст.
- До `Save` файлы не меняются. Нарушения чистой архитектуры подсвечивает,
  запрещённые связи провести не даёт.

### Установка

Есть два варианта — на выбор:

```bash
# Вариант А: весь стек + IDE одной командой (вместо Шага 2 выше)
pip install "pacage-studio[full] @ git+https://github.com/senia-glitch/pacage-studio-ide.git"

# Вариант Б: IDE отдельно, поверх уже установленных трёх пакетов
pip install "pacage-studio @ git+https://github.com/senia-glitch/pacage-studio-ide.git"
Проверка: studio help показывает список команд.

Использование (в корне проекта)
studio init      # один раз: создаёт .studio/ с настройками
studio scan      # построить граф по коду (код не трогает)
studio dev       # поднять интерфейс: http://127.0.0.1:8777
studio validate  # проверить чистую архитектуру
studio save      # записать правки из графа обратно в код
Остановка интерфейса — Ctrl+C. Подробный разбор интерфейса, режимов канваса и настроек — в ИНСТРУКЦИЯ.md репозитория pacage-studio-ide.

Ежедневный workflow со studio
Правишь код как обычно → studio scan обновляет граф.
Правишь архитектуру в интерфейсе → Save пишет изменения в код.
Перед коммитом → studio validate: ноль нарушений.
Единственное правило: правишь граф — жми Save, иначе файлы не изменятся.
