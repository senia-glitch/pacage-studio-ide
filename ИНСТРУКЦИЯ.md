# Studio — как запустить и работать (инструкция с нуля)

Здесь только практика: команды, куда смотреть, что должно получиться.
Студия только читает код — она ничего не пишет в проект.

---

## 1. Проверка перед стартом (1 минута)

Открой PowerShell и выполни:

```powershell
studio help
```

Должен показаться список команд (`scan`, `dev`, `list`, `help`).
Если команда не найдена — из папки пакета выполни:

```powershell
pip install -e .
```

`studio help` после этого обязана работать. Всё ниже запускается из **любого места** —
важен только флаг `--project`, указывающий на твой проект.

### Полный стек одной командой (необязательно)

По умолчанию студия ставится голой — только `pydantic`, чужих пакетов нет.
Чтобы вместе со студией приехал инфраструктурный стек
(`fastbase` + `core-package` + `event-infra`), ставь с флагом `[full]`:

```powershell
pip install -e ".[full]"
```

## 2. Подготовь пробный проект (копипаст, 2 минуты)

Демо-проект — обычная папка с кодом в раскладке стека
(папка `C:\Temp\opencode\myapp`, пробелов в пути нет — так надёжнее):

```powershell
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\api\v1\routes"
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\scenarios"
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\utils"
```

Положи пять файлов:

```powershell
Set-Content -Path "C:\Temp\opencode\myapp\.env.fastbase" -Value @'
FAT_ROUTES_PACKAGE=app.api.v1.routes
FAT_CORE_DISCOVER=app.scenarios
FAT_API_PREFIX=/api/v1
'@

Set-Content -Path "C:\Temp\opencode\myapp\models.py" -Value @'
from sqlmodel import SQLModel


class Order(SQLModel, table=True):
    __tablename__ = "orders"
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\api\v1\routes\views.py" -Value @'
from fastapi import APIRouter
from core import run

router = APIRouter(tags=["orders"])


@router.post("/orders")
async def create_order(payload: dict):
    return await run("create_order", payload)
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\scenarios\orders.py" -Value @'
from core import BaseScenario, register_scenario
from app.utils.money import calc_total


@register_scenario("create_order")
class CreateOrderScenario(BaseScenario):
    async def execute(self, dto):
        await self._db.create("orders", {})
        calc_total(1)
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\utils\money.py" -Value @'
def calc_total(x):
    return x
'@
```

Разбор: endpoint `POST /orders` диспатчит сценарий `create_order`,
тот пишет в таблицу `orders` (модель `Order`) и зовёт helper `calc_total`.

## 3. Первое сканирование

```powershell
studio --project "C:\Temp\opencode\myapp" scan
studio --project "C:\Temp\opencode\myapp" list
```

Что должно получиться:

| Команда | Ожидаемый результат |
|---------|---------------------|
| `scan`  | `scan: endpoints 1, scenarios 1, io 1, models 1` |
| `list`  | `endpoint POST /orders`, `scenario create_order`, `io: _db.create(orders) -> Order` |

Появилась папка `C:\Temp\opencode\myapp\.studio` — там `graph.json` (граф),
`studio.log` (лог последнего запуска) и `.gitignore` (не коммитить).
Код проекта `scan` не меняет ни на байт.

## 4. Запуск интерфейса

```powershell
studio --project "C:\Temp\opencode\myapp" dev
```

Открой в браузере: **http://127.0.0.1:8777**

Если графа ещё нет — `dev` построит его сам. Остановить позже: `Ctrl+C`.

## 5. Тур по интерфейсу

**Шапка (сверху):** кнопки режимов `Сценарий` / `Обзор`, справа — зум
(`−` / проценты / `+` / `вписать` / `1:1`) и счётчик «узлов · связей».
Кнопок записи (Save/Validate/Scan) нет и быть не может — студия только смотрит.

**Левая панель «Сценарии»:** список сгруппирован по endpoint'ам
(`GET /users · tags`), сценарии без endpoint'а — в группе «(без endpoint)».
Точка `· io N` — число операций с БД. Клик — открыть путь сценария.

**Канвас (центр), режим «Сценарий»:** путь одного запроса слева направо:

- `representation` — узел endpoint'а (`GET /orders`, под ним имя функции);
- `logic` — узел сценария (имя + класс); стрелка `run("...")` между ними;
  вложенный сценарий (если сценарий зовет другой через `run`) — полупрозрачный
  узел ниже, клик — перейти в его путь;
- полка `helpers` под representation/logic — локальные модули
  (Depends, схемы, исключения, утилиты); роль написана под именем;
- `io` — узлы `_db.create(orders)`, `_db.query(...)` со ссылкой на строку;
- `model` — узлы моделей (`Order · orders`), стрелка от io — какая таблица.

**Обзор:** сетка всех сценариев; справа — колонка shared-моделей,
к ней бледными линиями идут сценарии, которые эту модель трогают.

**Инспектор (справа):** клик по любому узлу — kind, label, файл, строка,
метод/таблица/роль и кнопка `code view` (исходник файла, только чтение).

**Навигация:** тяни фон — панорама; колесо — зум; `Esc` — снять выделение.
Глубокая ссылка на конкретный сценарий: `http://127.0.0.1:8777/#s=<id>`,
обзор: `#overview`.

## 6. Повседневный цикл (шпаргалка)

```powershell
studio --project "<путь>" scan   # обновил граф по новому коду
studio --project "<путь>" dev    # посмотрел путь в браузере
studio --project "<путь>" list   # быстро глянуть сценарии в терминале
```

Правка кода → `scan` → граф актуален. Старый граф (версия ≠ 2) студия
перестроит сама при первом запросе.

## 7. Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| `studio` не найдена | `pip install -e .` из папки пакета |
| `no graph: run studio scan first` | Сначала `studio --project ... scan` |
| Порт занят при `dev` | Другой `dev` уже висит; останови его (`Ctrl+C`) или смени порт: `studio --project ... dev --port 8778` |
| Пустой список сценариев | Проверь `@register_scenario("<name>")` на классах и что `FAT_CORE_DISCOVER` указывает на пакет со сценариями |
| Сценарий в «(без endpoint)» | Ни один endpoint не зовёт его через `run("<name>")` — это нормально для вложенных сценариев |
| Нет io-узлов | В `execute` нет `self._db.<method>(...)` — вызовы порта ищутся только в `execute` |
| Нет модели у io | Таблица не найдена в `models.py` (класс SQLModel с `__tablename__` только в корне) |
| Пустой канвас | Проверь, что в проекте есть `.py`-файлы вне `tests/`, `alembic/`, `docs/`, `.venv` |
| Кракозябры в консоли | Только отображение PowerShell; лечится `chcp 65001` |
| Нужны детали для отладки | Открой `\.studio\studio.log` — шаги последнего запуска |

Закрытие: в окне с `dev` нажать `Ctrl+C`. Проект при работе студии
запускать не нужно — она работает только с кодом как с текстом.
