# Studio — как запустить и работать (инструкция с нуля)

Здесь только практика: команды, куда смотреть, что должно получиться.
Режим **Просмотр** — работа с тем, что есть: карта кода и созданных сценариев,
правка описаний узлов (маркерами в код) и доменов. Режим **Конструктор** —
только создание нового сценария (мастер) и перенос плана в файлы (кнопка
**Создать файлы**). Существующий код проекта без явного действия не правится.

---

## 1. Проверка перед стартом (1 минута)

Открой PowerShell и выполни:

```powershell
studio help
```

Должен показаться список команд (`scan`, `dev`, `list`, `scaffold`, `export`, `reset`, `help`).
Если команда не найдена — установи пакет в venv проекта:

```powershell
python -m pip install --upgrade --force-reinstall "pacage-studio[full] @ git+https://github.com/senia-glitch/pacage-studio-ide.git"
```

Подробная инструкция: [УСТАНОВКА.md](УСТАНОВКА.md).

`studio help` после этого обязана работать. Всё ниже запускается из **любого места** —
важен только флаг `--project`, указывающий на твой проект.

---

## 2. Подготовь пробный проект (копипаст, 2 минуты)

Демо-проект — обычная папка с кодом в раскладке стека
(папка `C:\Temp\opencode\myapp`, пробелов в пути нет — так надёжнее):

```powershell
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\api\v1\routes"
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\scenarios"
New-Item -ItemType Directory -Force -Path "C:\Temp\opencode\myapp\app\utils"
```

Положи пять файлов:

```powershell
Set-Content -Path "C:\Temp\opencode\myapp\.env.fastbase" -Value @'
FAT_ROUTES_PACKAGE=app.api.v1.routes
FAT_CORE_DISCOVER=app.scenarios
FAT_API_PREFIX=/api/v1
'@

Set-Content -Path "C:\Temp\opencode\myapp\models.py" -Value @'
from sqlmodel import SQLModel


class Order(SQLModel, table=True):
    __tablename__ = "orders"
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\api\v1\routes\views.py" -Value @'
from fastapi import APIRouter
from core import run

router = APIRouter(tags=["orders"])


@router.post("/orders")
async def create_order(payload: dict):
    return await run("create_order", payload)
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\scenarios\orders.py" -Value @'
from core import BaseScenario, register_scenario
from app.utils.money import calc_total


@register_scenario("create_order")
class CreateOrderScenario(BaseScenario):
    async def execute(self, dto):
        await self._db.create("orders", {})
        calc_total(1)
'@

Set-Content -Path "C:\Temp\opencode\myapp\app\utils\money.py" -Value @'
def calc_total(x):
    return x
'@
```

Разбор: endpoint `POST /orders` диспатчит сценарий `create_order`,
тот пишет в таблицу `orders` (модель `Order`) и зовёт helper `calc_total`.

## 3. Первое сканирование

```powershell
studio --project "C:\Temp\opencode\myapp" scan
studio --project "C:\Temp\opencode\myapp" list
```

Что должно получиться:

| Команда | Ожидаемый результат |
|---------|---------------------|
| `scan`  | `scan: endpoints 1, scenarios 1, io 1, models 1` |
| `list`  | `endpoint POST /orders`, `scenario create_order`, `io: _db.create(orders) -> Order` |

Появилась папка `C:\Temp\opencode\myapp\.studio` — там `graph.json` (граф),
`studio.log` (лог последнего запуска) и `.gitignore` (не коммитить).
Код проекта `scan` не меняет ни на байт.

---

## 4. Запуск интерфейса

```powershell
studio --project "C:\Temp\opencode\myapp" dev
```

Открой в браузере: **http://127.0.0.1:8777**

Если графа ещё нет — `dev` построит его сам. Остановить позже: `Ctrl+C`.

## 5. Тур по интерфейсу

**Шапка (сверху):** категории с русскими подписями — **Режим**
(`Просмотр` / `Конструктор`), **Вид** (`Сценарий` / `Обзор`), **Содержимое**
(`Описание` / `Критерии` — секции в узлах), **Масштаб**
(`−` / проценты / `+` / `вписать` / `1:1`), **Действия** (`Экспорт ▾`,
`Сохранить`, `Создать файлы`, `Очистить план` — записи видны только
в Конструкторе) и счётчик «узлов · связей».
В Просмотре правятся описания узлов и домены сценариев (инспектор справа);
в Конструкторе создаются новые сценарии, а файлы-скелеты — только по
«Создать файлы»; план хранится в `.studio/plan.json` и чистится кнопкой
«Очистить план».

**Левая панель «Сценарии»:** поиск + список, сгруппированный в два уровня —
«HTTP-метод → домен» (GET/POST/PUT/PATCH/DELETE → «без метода», домены по
алфавиту, «без домена» последним). `· io N` — число операций с БД, `↻` —
сценарий вызывается из нескольких методов, `✦ план` — сценарий создан
в Конструкторе (файла ещё нет). Клик — открыть путь сценария;
свёрнутость групп при этом сохраняется. Домен задаётся в инспекторе
(клик по сценарию на канвасе → поле «Домен»).

**Канвас (центр), режим «Сценарий»:** путь одного запроса слева направо:

- `representation` — узел endpoint'а (цветная плашка метода, имя функции);
- `logic` — узел сценария (имя + класс, плашка домена); стрелка `run("...")` между ними;
  вложенный сценарий (если сценарий зовет другой через `run`) — полупрозрачный
  узел ниже, клик — перейти в его путь;
- полка `helpers` под representation/logic — локальные модули
  (Depends, схемы, исключения, утилиты); роль написана под именем;
- `io` — узлы `_db.create(orders)`, `_db.query(...)` со ссылкой на строку;
- `model` — узлы моделей (`Order · orders`), стрелка от io — какая таблица;
- в узлах — секции «описание» и «критерии» (полный текст со скроллом,
  включаются/выключаются кнопками «Содержимое» в шапке).

Слои оформлены зонами — пунктирный прямоугольник с подписью слоя и счётчиком
узлов; зоны не пересекаются, сталкивающиеся автоматически раздвигаются.

**Обзор:** все сценарии плиткой, сгруппированные «HTTP-метод → домен»
(подзаголовки с цветным кружком метода); справа — колонка shared-моделей,
к ней бледными линиями идут сценарии, которые эту модель трогают.

**Инспектор (справа):** клик по любому узлу — kind, файл, строка,
метод/таблица/роль, описание и кнопка «Открыть исходник» (файл проекта, только чтение).
Поля «Описание» и «Домен» редактируются прямо здесь: кнопка
«Сохранить изменения» (Ctrl+S) пишет описание **в код** блоком
`# studio: description start … end`, домен — в план. Правка видна на узле
сразу (черновик), «Отменить правки» — откат. У операций БД описание не
редактируется (оно живёт в сценарии-родителе).

**Режим Конструктор** (кнопка в шапке):

- слева панель скрывается, справа — мастер «Новый сценарий»: название,
  описание, критерии приёмки, домен, HTTP-эндпоинт (метод, путь)
  и операции БД;
- кнопка «Создать» добавляет область, сценарий и связи и **автоматически
  переключает в Просмотр**, где путь нового сценария сразу виден
  (узел с пометкой «✦ план», пока файлы не созданы);
- если создание оборвалось на середине — созданные узлы откатываются,
  полу-областей не остаётся;
- **Создать файлы** — модальное окно со списком: что будет создано, обновлено,
  дописано в models.py и что будет пропущено; после подтверждения файлы
  создаются с маркером `# studio: scaffold ...`, сценарий становится кодом;
- **Очистить план** — удалить `.studio/plan.json` (созданные сценарии и связи)
  с подтверждением; код проекта не меняется, описания, сохранённые маркерами,
  остаются в файлах;
- **Экспорт ▾** → Markdown / JSON / копировать в буфер.

**Навигация:** тяни фон — панорама; колесо — зум; тяни за заголовок узла —
перетащить (зоны следуют); `Esc` — снять выделение.
Глубокая ссылка на конкретный сценарий: `http://127.0.0.1:8777/#s=<id>`,
обзор: `#overview`.

## 6. Повседневный цикл (шпаргалка)

```powershell
studio --project "<путь>" scan     # обновил граф по новому коду (план сохранится)
studio --project "<путь>" dev      # посмотрел путь в браузере
studio --project "<путь>" list     # быстро глянуть сценарии в терминале
studio --project "<путь>" export   # md-инструкция/JSON для AI-агента
studio --project "<путь>" scaffold # показать/создать скелеты из плана (CLI)
studio --project "<путь>" metadata # перенести описание/критерии в код (--dry-run, --yes)
studio --project "<путь>" reset    # выбросить план (.studio/plan.json)
```

Правка кода → `scan` → граф актуален, патчи плана применяются поверх скана.
Старый граф (версия ≠ 4) студия перестроит сама при первом запросе.
`reset` спрашивает подтверждение; в неинтерактивном режиме отвечает «нет»
(используй `--yes`).

## 7. Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| `studio` не найдена | `pip install -e .` из папки пакета |
| `no graph: run studio scan first` | Сначала `studio --project ... scan` |
| Порт занят при `dev` | Другой `dev` уже висит; останови его (`Ctrl+C`) или смени порт: `studio --project ... dev --port 8778` |
| Пустой список сценариев | Проверь `@register_scenario("<name>")` на классах и что `FAT_CORE_DISCOVER` указывает на пакет со сценариями |
| Сценарий в «(без endpoint)» | Ни один endpoint не зовёт его через `run("<name>")` — это нормально для вложенных сценариев |
| Нет io-узлов | В `execute` нет `self._db.<method>(...)` — вызовы порта ищутся только в `execute` |
| Нет модели у io | Таблица не найдена в `models.py` (класс SQLModel с `__tablename__` только в корне) |
| Пустой канвас | Проверь, что в проекте есть `.py`-файлы вне `tests/`, `alembic/`, `docs/`, `.venv` |
| Правка описания не появилась | Правки сохраняются кнопкой «Сохранить изменения» (Ctrl+S) в инспекторе; проверь, что файл перечитан — «Обновить из кода» |
| В Конструкторе «ошибка создания: HTTP 404» | Пакет устарел или сервер не перезапущен: `pip install --upgrade "git+https://github.com/senia-glitch/pacage-studio-ide.git"` и перезапусти `studio dev` |
| Скелет создался, а после scan появился дубль | id планового узла не совпал с id сканированного файла — очисти план («Очистить план») и создай сценарий заново |
| `FAT_ROUTES_PACKAGE` игнорируется | Значение должно быть dotted-путём из идентификаторов (`app.api.v1.routes`), без `..` и абсолютных путей — предупреждение в `studio.log` |
| Кракозябры в консоли | Только отображение PowerShell; лечится `chcp 65001` |
| Нужны детали для отладки | Открой `\.studio\studio.log` — шаги последнего запуска |

Закрытие: в окне с `dev` нажать `Ctrl+C`. Проект при работе студии
запускать не нужно — она работает только с кодом как с текстом.
